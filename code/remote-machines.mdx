---
title: "Remote machines"
description: "Run Aristra Code on another machine over SSH, with that machine's files, sandbox and chats, from your own terminal."
---

```sh
aristra --remote dev-box                       # Aristra Code, working on dev-box
aristra --remote dev-box --folder ~/code/api
aristra --remote me@10.0.0.5 run "run the test suite and summarize failures" -o json
aristra --remote dev-box login                 # sign the remote machine in, with a code
aristra --remote dev-box sessions --all
```

`--remote <host>` takes an SSH destination as `ssh` does (a host, `user@host` or an alias from `~/.ssh/config`) and works with every command. Your terminal connects with `ssh` and talks to Aristra Code on that machine: its files, its sandbox, its settings, its chats and its sign-in. Your terminal is only the screen. No port opens on either machine, and nothing is copied between them.

## Set it up

1. **Install Aristra Code on the remote machine:**

   ```sh
   curl -fsSL https://aristralabs.com/install.sh | sh
   ```

2. **Sign it in.** The browser on your computer can't reach the remote machine, so sign in with a code:

   ```sh
   aristra --remote dev-box login
   ```

   Enter the code it shows at aristralabs.com on any device. The remote machine keeps its own sign-in.

3. **Start working:** `aristra --remote dev-box`. The header names the machine.

## Good to know

- **The folder** is where SSH lands (usually your home folder) unless `--folder` names one. A relative `--folder` starts from there.
- **Attaching a file by path** works for files on the remote machine. Uploading a file from your computer into a remote chat isn't supported yet.
- **The connection carries the chat.** When it drops, a turn running there stops. To leave work running on the remote machine, run `aristra` there inside `tmux` or `screen` instead.
- `ARISTRA_SSH` names another program to use in place of `ssh`.
