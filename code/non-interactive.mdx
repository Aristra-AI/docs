---
title: "Non-interactive mode"
description: "Run Aristra Code from scripts and CI with aristra run or aristra -p: one turn, text or JSON output, and exit statuses you can act on."
---

`aristra run` (or `aristra -p`) runs one turn and exits. It never waits on a prompt: a step that would ask for approval is declined, the model is told why, and the run exits with status 3.

```sh
aristra run "fix the failing test"
git diff | aristra run "write a commit message for this" -o json
aristra run -o stream-json --partial --permission-mode auto --allow "shell(npm test:*)" "make the tests pass"
```

Text piped on stdin is added after the prompt, separated by a blank line.

## Options

| Option | Meaning |
|---|---|
| `-o, --output text\|json\|stream-json` | `text` prints the final reply. `json` prints one `result` object. `stream-json` prints events as they happen, one JSON object per line (also `--output-format`) |
| `--partial` | With `stream-json`, also `delta` events as text is written |
| `-m, --model <id>`, `--source <id>` | The model and where it comes from. Without them, your default |
| `--permission-mode <mode>` | `manual` (or `default`), `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions` or `read_only` |
| `--permission-prompts host\|none` | Where a step that would ask goes: both decline it, as nobody is there to answer |
| `--allow-dangerously-skip-permissions` | Let the chat switch to `bypassPermissions` later |
| `--allow <rule>`, `--deny <rule>` | Permission rules for this run only, such as `shell(npm test *)`. Repeatable. A deny anywhere still wins |
| `--add-dir <path>` | Another folder the chat may work in. Repeatable |
| `--folder <path>` | The folder to work in; default, the current one |
| `--plugin-dir <path>` | Load a plugin from a folder or `.zip` for this run only; a folder of plugins loads each one. Repeatable |
| `-c, --continue`, `-r, --resume <id>` | Go on in this folder's newest chat, or in that chat |
| `--fork-session` | With `--continue` or `--resume`: go on in a copy, leaving the chat as it was |
| `--no-session-persistence` | Keep nothing: the run's chat is deleted when it ends |
| `-w, --worktree [name]` | Work in a git worktree of the repository, made or reused, kept afterwards |
| `--max-turns <n>` | End after `n` model rounds (also `ARISTRA_MAX_TURNS`) |
| `--run-budget <seconds>` | At 80% of this time, tell the agent to stop exploring and deliver what it has |
| `--json-schema <schema>` | The reply must be a value matching this JSON Schema; it is returned as `structuredOutput` |
| `--system-prompt <text>`, `--system-prompt-file <path>` | Replace Aristra's system prompt for a new chat. Your `AGENTS.md` still applies |
| `--append-system-prompt <text>`, `--append-system-prompt-file <path>` | Add to the end of a new chat's system prompt |
| `--agent <agent>` | Run a new chat as one of your [custom agents](/code/guides/subagents#custom-agents) |
| `--settings <file-or-json>` | Extra settings for this run only, over your own and the project's |
| `--setting-sources <list>` | Which settings files to read: `user`, `project`, `local`, comma-separated; `""` for none |
| `--mcp-config <config>` | MCP servers for this run, as JSON or a file: `{"mcpServers": {...}}`. Repeatable |
| `--strict-mcp-config` | Only the `--mcp-config` servers |
| `--input-format stream-json` | Read user messages from stdin, one JSON object a line; each starts a turn |
| `--usage-file <path>` | Write the run's token usage there as JSON |
| `--no-daemon` | Use a runtime of its own that ends with the run |
| `--dangerously-skip-sandbox` | Run commands outside the sandbox. Only where the machine itself is the boundary: a CI runner, a container, a VM |
| `--dangerously-skip-permissions` | Start in `bypassPermissions`. Refused to root unless `IS_SANDBOX=1` |
| `--verbose` | With `--output json`, every event in one JSON array |

`--remote <host>` before `run` runs it on another machine over SSH; see [Remote machines](/code/remote-machines).

## In CI

On a computer signed in to Aristra, `aristra setup-token` prints a token that runs models on your account's Aristra balance for a year, and nothing else. Store it as a CI secret named `ARISTRA_TOKEN`:

```sh
export ARISTRA_TOKEN=...   # from aristra setup-token
aristra run --source aristra "summarize the failing tests" < test-output.txt
```

Revoke it by signing its device out on the Aristra website.

<Warning>
In CI there is nobody to approve steps. Allow exactly what the job needs with `--allow`, or use `--permission-mode auto` to let Aristra's reviewer decide, and check the exit status.
</Warning>

## Exit status

| Status | When |
|---|---|
| 0 | The turn completed |
| 1 | It failed: an error, the runtime unreachable, `--max-turns` reached, or no matching `--json-schema` value |
| 2 | A usage mistake: an unknown option, no prompt |
| 3 | It completed, but at least one step was declined because nobody could approve it |
| 130 | Ctrl+C stopped it |

A step refused by a deny rule doesn't make the status 3: the rule did what it says. Both kinds are listed in `result.permissionDenials`. With `--permission-mode auto`, the reviewer decides what would ask; after it blocks 3 steps in a row, or 20 in a chat, the run stops with status 1.

## Messages on stdin

With `--output stream-json --input-format stream-json`, each line on stdin is a message, and turns run one after another in the same chat:

```json
{"type":"user","message":{"role":"user","content":"Fix the failing test"}}
{"type":"user","message":{"role":"user","content":[{"type":"text","text":"Now run the linter"}]}}
{"type":"control_request","request_id":"r1","request":{"subtype":"interrupt"}}
```

`interrupt` stops the running turn, and `end_session` ends the run once its turns have. The run ends when stdin does.

## Output events

Every `stream-json` event has `"schema": "aristra.run.v1"` and a `type`. Fields are added in later versions; none are removed or renamed.

<AccordionGroup>
  <Accordion title="init: what the run uses">
    ```json
    {"schema":"aristra.run.v1","type":"init","version":"1.2.1","session":"ses_8f1c…","source":"aristra","model":"gemini-3.8-flash","payer":"aristra_credits","mode":"default","folder":"/home/ci/repo","sandbox":true}
    ```

    `payer` is `aristra_credits` (your Aristra balance; the name is kept for scripts), `own_key`, `subscription`, `local` or `none`.
  </Accordion>
  <Accordion title="item: something in the turn finished">
    `item.kind` is `user`, `reply`, `reasoning`, `step`, `notice` or `compaction`. A step has its `tool`, `type`, `title`, `status`, `output`, `durationMs`, the file `changes` it made, and in Auto mode the reviewer's `review`.

    ```json
    {"schema":"aristra.run.v1","type":"item","item":{"kind":"step","id":"itm_51a2…","tool":"shell","type":"command","title":"npm test","status":"completed","output":"Tests: 42 passed","durationMs":5120}}
    ```
  </Accordion>
  <Accordion title="delta: text as it is written (with --partial)">
    ```json
    {"schema":"aristra.run.v1","type":"delta","item":"itm_9c0e…","stream":"text","text":"The test failed because "}
    ```
  </Accordion>
  <Accordion title="approval: a step that asked, and how it was decided">
    ```json
    {"schema":"aristra.run.v1","type":"approval","step":"itm_77b3…","tool":"shell","title":"git push","decision":"declined","reason":"No one was there to approve this (an unattended run), so it did not run. This command requires approval"}
    ```
  </Accordion>
  <Accordion title="result: last (the only line with --output json)">
    ```json
    {"schema":"aristra.run.v1","type":"result","status":"completed","exitCode":0,"session":"ses_8f1c…","turn":"trn_2d4a…","result":"The test now passes: …","usage":{"input":18234,"output":912,"cached":12000,"cacheWrite":0,"reasoning":256},"payer":"aristra_credits","durationMs":48211,"unanswered":0,"permissionDenials":[]}
    ```

    | Field | Meaning |
    |---|---|
    | `status` | `completed`, `failed` or `interrupted` |
    | `exitCode` | The process's exit status |
    | `session`, `turn` | Ids, for `--resume` and `aristra attach` |
    | `result` | The final reply |
    | `usage` | Tokens: `input`, `output`, `cached`, `cacheWrite`, `reasoning` |
    | `unanswered` | Steps declined because nobody could approve them |
    | `permissionDenials` | Each declined step: `step`, `tool`, `title`, `reason` |
    | `error`, `errorKind` | Why it failed: `auth`, `entitlement`, `rate_limited`, `overloaded`, `context_overflow`, `invalid_request`, `network`, `refused` or `unknown` |
    | `retryAt` | When the provider said it may be asked again (Unix milliseconds) |
    | `structuredOutput` | With `--json-schema`, the value the model gave |
    | `terminalReason` | `max_turns` or `structured_output_retries`, when a limit ended the turn |
  </Accordion>
</AccordionGroup>
