A hook is a command of yours that Aristra Code runs on an event: before a tool runs, after it ran, when you send a message, when a turn ends. Use one to check commands against your team's rules, format a file after an edit, log what the agent did, or add context to a prompt. Hooks use Claude Code's format: the same events, stdin and answers. Tool names are Aristra Code's, so a matcher naming Claude Code's tools (`Bash`, `Edit`, `Write`) needs Aristra Code's names (`shell`, `edit_file`, `write_file`). `aristra import claude-code` changes them for you, and an `if` rule may use either.

## Declare a hook

Hooks come from your own settings (`~/.aristra/settings.json`), a trusted folder's `.aristra/settings.json`, a [plugin](/code/extend/plugins)'s `hooks/hooks.json`, a [custom agent](/code/guides/subagents#custom-agents)'s `hooks` (active while that agent runs) and a [managed policy](/code/configure/managed-policy). Hooks in `.aristra/settings.local.json` are not run. In settings:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "shell|write_file",
        "hooks": [
          { "type": "command", "command": "~/.aristra/hooks/check.sh", "timeout": 10, "onFailure": "block" }
        ]
      }
    ],
    "PostToolUse": [
      { "matcher": "edit_file|write_file", "hooks": [{ "type": "command", "command": "npx prettier --write \"$ARISTRA_PROJECT_DIR\"" }] }
    ],
    "UserPromptSubmit": [
      { "hooks": [{ "type": "command", "command": "~/.aristra/hooks/add-ticket-context.sh" }] }
    ]
  }
}
```

| Field | Meaning |
|---|---|
| `matcher` | What the hooks apply to: the tool name for tool events and `PermissionDenied`, the agent type, the notification type, the compaction trigger, the command name (`UserPromptExpansion`), the start source (`SessionStart`) or the error (`StopFailure`). Other events ignore it. A name, names joined with `\|`, or a regular expression. Leave it out to match everything |
| `type` | `command`, or `http`: the event is POSTed as JSON to `url`, and a 2xx body is read as the hook's answer (`allowedHttpHookUrls` limits where; `headers` take `$VAR` from `allowedEnvVars` only). It doesn't run on `SessionStart`, and it isn't sent to a private network address other than this computer's |
| `if` | A permission rule the call must match, such as `Bash(git *)` |
| `once` | Run once in the chat |
| `async` | Run in the background, never blocking (`asyncRewake`: its exit 2 is said in the chat) |
| `command` | Run through the shell |
| `args` | Run `command` as a program with these arguments, without a shell |
| `timeout` | Seconds, 60 by default, at most 300 (`SessionEnd`: 10). At its timeout, and when you stop the turn, the hook and everything it started are stopped |
| `onFailure` | `"block"`: a hook that crashes, times out or prints unreadable JSON blocks where its event can, instead of being skipped |

## Approve a hook

A hook runs your code with your full access, outside the sandbox. So it runs only after you approve its event and exact command, once. Until then it is skipped and the chat says so.

```sh
aristra hooks list                                     # every hook, approved or not
aristra hooks approve PreToolUse ~/.aristra/hooks/check.sh
aristra hooks revoke PreToolUse ~/.aristra/hooks/check.sh
aristra hooks test PreToolUse --tool shell --input '{"command": "git push --force"}'
aristra hooks test UserPromptSubmit --prompt "deploy to production"
```

Changing a hook's command makes it a new hook to approve. `/hooks` in a chat lists your hooks and which still need approval. Aristra Desktop's Settings list them with Approve and Revoke.

A plugin's hooks and a managed policy's hooks don't ask one by one: installing the plugin, or your organization's policy, is the consent. `disableAllHooks: true` turns off every hook except your organization's (set in the policy, it turns those off too). A policy's `allowManagedHooksOnly: true` runs only the policy's hooks and those of plugins the policy turns on.

## Events

| Event | When | The payload adds |
|---|---|---|
| `SessionStart` | A chat's first turn since Aristra started: `source` is `startup` for a new chat, `resume` for an earlier one. Not in a subagent's chat | `source` |
| `UserPromptSubmit` | You sent a message, before the model sees it | `prompt` |
| `UserPromptExpansion` | You typed a skill or prompt command, before it is used | `expansion_type`, `command_name`, `command_args`, `command_source`, `prompt` |
| `PreToolUse` | Before a tool call, before the permission check | `tool_name`, `tool_input`, `tool_use_id` |
| `PermissionRequest` | A tool call is about to ask you (or, with nobody to ask, be declined) | `tool_name`, `tool_input`, `tool_use_id`, `permission_suggestions` |
| `PostToolUse` | After a tool call ran | `tool_name`, `tool_input`, `tool_use_id`, `tool_response`, `duration_ms`, `mcp_server` |
| `PostToolUseFailure` | A tool call failed while running | `tool_name`, `tool_input`, `tool_use_id`, `error`, `is_interrupt`, `duration_ms` |
| `PostToolBatch` | All the calls of one reply have finished | `tool_calls` |
| `Notification` | An approval has waited 6 seconds, or a reply has waited a minute for you | `message`, `notification_type` |
| `PermissionDenied` | Auto mode's reviewer denied a tool call; a hook that returns `hookSpecificOutput.retry: true` lets the model try it again | `tool_name`, `tool_input`, `tool_use_id`, `reason` |
| `Stop` | The turn is about to end | `stop_hook_active`, `last_assistant_message`, `background_tasks`, `session_crons` |
| `SubagentStart` | An agent is about to start | `agent_id`, `agent_type` |
| `SubagentStop` | An agent's turn is about to end | as `Stop`, with `agent_id`, `agent_type` and `agent_transcript_path` (always empty) |
| `StopFailure` | A turn ended on a model error | `error`, `error_details`, `last_assistant_message` |
| `PreCompact` | Before older messages are summarized | `trigger` (`auto` or `manual`), `custom_instructions` |
| `PostCompact` | After they were | `trigger`, `compact_summary` |
| `SessionEnd` | The chat was deleted, or Aristra is stopping | `reason` |

Every payload also has `hook_event_name`, `session_id`, `transcript_path` (always empty), `cwd`, `permission_mode` and, during a turn, `prompt_id` and `turn_id`; in a subagent's chat `agent_id` and `agent_type`; and `effort` when the chat sets one. It arrives as JSON on the hook's stdin. The hook runs with your environment plus `ARISTRA_PROJECT_DIR` (and `CLAUDE_PROJECT_DIR`), the chat's folder.

## Answers

| The hook | Means |
|---|---|
| Exits 0 and prints nothing | Go on |
| Exits 2 | Block the tool call, the prompt or what the event is about, with stderr as the reason. From `PostToolUse`: stderr goes to the model with the result. From `Stop`: keep the turn going, with stderr for the model |
| Prints `{"decision": "block", "reason": "..."}` | Block, with that reason |
| Prints `hookSpecificOutput.permissionDecision`: `"deny"`, `"ask"` or `"allow"` | Refuse the call, make it ask, or skip the prompt (deny rules, ask rules and safety checks still apply, and a step that always needs you still asks) |
| From `PermissionRequest`, prints `hookSpecificOutput.decision: {"behavior": "allow" \| "deny", ...}` | Answer the approval for you |
| From `PreToolUse`, prints `hookSpecificOutput.updatedInput` | Run the tool with these arguments instead |
| Prints `additionalContext` (or plain text from `UserPromptSubmit`, `UserPromptExpansion` and `SessionStart`) | Added for the model |
| Prints `systemMessage` | Shown in the chat |
| Prints `continue: false` with `stopReason` | Stop: the call or prompt is refused, or the turn ends |
| From `PostToolUse`, prints `hookSpecificOutput.updatedToolOutput` (`updatedMCPToolOutput` for an MCP tool) | The model reads this instead of the tool's output |
| From `PreCompact`, prints text | Added to the summary's instructions |

An event's hooks run side by side. Any block wins (deny over ask over allow), every context counts, and the last changed input is used. Stop hooks and a `/goal` check together can keep a turn going up to 8 times in a row without the model calling a tool (`ARISTRA_STOP_HOOK_BLOCK_CAP` changes this); a hook should return success when `stop_hook_active` is true.
