The Aristra CLI is the `aristra` command: Aristra Code in your terminal. Every subcommand shows its usage with `--help`; a few show it as a usage error (status 2). For the commands you type inside a chat, see [Commands](/code/reference/commands).

```text
aristra [options] [prompt]          Aristra Code in this folder
aristra run [options] [prompt]      one turn, non-interactive (also: aristra -p or --print, as the first argument)
aristra <command> ...
```

Anything that isn't a subcommand is a prompt: `aristra fix the build` starts a chat with "fix the build".

## Global options

| Option | Does |
|---|---|
| `--remote <host>` | Run on another machine over SSH, before or after the command. See [Remote machines](/code/remote-machines) for the commands that stay on this computer |
| `-v`, `--version` | Print the version |
| `-h`, `--help` | List the subcommands |
| `--help-agent` | List the interactive options |

Subcommands exit `0` on success, `1` on failure (the message on stderr) and `2` for a usage mistake. `aristra run` adds `3` and `130`; see [Non-interactive mode](/code/non-interactive#exit-status). `aristra serve` exits with the runtime's own status (`3`: a runtime already runs for this home). `aristra` exits `130` when you leave the first-run screens, as with "No, exit".

## Start a chat

```text
aristra [options] [prompt...]
aristra resume [id]
aristra attach <id>
```

| Option | Does |
|---|---|
| `-c`, `--continue` | Continue this folder's newest chat |
| `-r`, `--resume <id>` | Continue that chat |
| `-m`, `--model <id>` | The model for a new chat |
| `--source <id>` | Where the model comes from: `aristra`, `chatgpt`, `openai`, `anthropic`, `gemini`, `ollama`, `lmstudio`, `custom` and others |
| `--agent <agent>` | Run the chat as one of your [custom agents](/code/guides/subagents#custom-agents) |
| `-w`, `--worktree [name]` | Work in a git worktree. See [Worktrees](/code/guides/git#worktrees) |
| `--permission-mode <mode>` | The starting mode: `manual` (or `default`), `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`, `read_only` |
| `--dangerously-skip-permissions` | Start in Bypass permissions. Refused to root unless `IS_SANDBOX=1` |
| `--allow-dangerously-skip-permissions` | Let the chat switch to Bypass permissions later |
| `--add-dir <path>` | Another folder the chat may work in. Repeatable |
| `--plugin-dir <path>` | Load a plugin from a folder or `.zip` for this chat. Repeatable |
| `--fullscreen` | Use the fullscreen renderer for this launch |
| `--folder <path>` | The folder to work in |
| `--cloud` | A [cloud chat](/code/cloud-chats), run by Aristra's cloud agent |
| `--incognito` | With `--cloud`: kept out of your account's lists |
| `--project <name>` | With `--cloud`: start the chat in that project |

`aristra resume` with no id opens a picker. `aristra resume <id>` and `aristra attach <id>` open that chat, whether it is idle, running or waiting for an approval.

## Non-interactive runs

`aristra run` (or `-p`) runs one turn for scripts and CI. Its options and output are in [Non-interactive mode](/code/non-interactive).

## Chats

```text
aristra sessions [--all | --cloud] [--limit <n>] [--json]
aristra sessions export <id> [--format md|json]
aristra sessions delete <id> [--yes]
aristra sessions import <id> [--folder <path>] [--source <id> --model <id>]
aristra sessions connect-folder <id> [--folder <path>]
aristra sessions download <id> [<key>]
```

| Form | Does |
|---|---|
| `sessions` | This folder's chats, newest first, from every surface. `--all` for every folder, `--cloud` for your account's cloud chats |
| `sessions export <id>` | Write the chat to `~/.aristra/exports/` |
| `sessions delete <id>` | Delete the chat and its files. `--yes` skips the question |
| `sessions import <id>` | Copy a cloud chat into a new chat on this computer |
| `sessions connect-folder <id>` | Give a cloud chat a folder on this computer |
| `sessions download <id>` | Download the files a cloud chat's agent made |

## Your account

| Command | Does |
|---|---|
| `aristra login [--device-code \| --browser]` | Sign in, in a browser or with a code (a code is the default over SSH or without a browser). While the browser sign-in waits, press c to use a code instead |
| `aristra logout` | Sign out and remove this computer from your account |
| `aristra setup-token [--name <name>]` | Print a token for CI that runs models on your Aristra balance for a year. See [In CI](/code/non-interactive#in-ci) |
| `aristra status [--json]` | Your account, the runtime and the model sources |

## Models and keys

| Command | Does |
|---|---|
| `aristra models [--source <id>] [--json]` | The models each source offers, with who pays and, for local models, whether they fit |
| `aristra keys add <provider>` | Add a provider key, or a tool's key: `brave` for web search, `e2b` for the sandbox (asked for hidden, or piped on stdin) |
| `aristra keys add custom [--url <address>] [--wire chat_completions\|responses\|anthropic] [--name <name>] [--model <id>]... [--no-key]` | A server of your own that speaks an OpenAI or Anthropic API |
| `aristra keys list` | Which keys are set, never the keys themselves |
| `aristra keys remove <provider>` | Remove a key |

## Extensions

| Command | Does |
|---|---|
| `aristra mcp add [-s scope] <name> [--env K=V]... [--secret K=V]... [--cwd <folder>] [--writable <folder>]... [--sandbox] -- <command> [args]` | Add an MCP server that runs as a program; `-s` is `local` (default), `project` or `user`. `--secret` keeps the value in your credential store, `--sandbox` runs it in the sandbox, with the network, writing only its own folder (`--cwd`, or the project), the `--writable` folders and package launcher caches |
| `aristra mcp add [-s scope] <name> --url <url> [--header K=V]... [--client-id <id>] [--client-secret <secret>]` | Add an MCP server at an address |
| `aristra mcp add-json [-s scope] <name> <json> [--client-secret <secret>]` | Add one from JSON |
| `aristra mcp add-from-claude-desktop [-s scope] [name...]` | Bring Claude Desktop's program (stdio) servers over (macOS) |
| `aristra mcp list [--json]`, `get <name>`, `test <name>`, `remove [-s scope] <name>` | List, inspect, try or remove servers |
| `aristra mcp reset-project-choices` | Forget your approvals of this project's `.mcp.json` servers |
| `aristra mcp trust <name>`, `untrust <name>` | Let a server's tools run without asking (a local or project server's in this project only), or not |
| `aristra mcp login <name> [--device-code]`, `logout <name>` | Sign in to a server with OAuth |
| `aristra hooks list [--json]`, `approve <event> <command>`, `revoke <event> <command>` | Your hooks, and approving them |
| `aristra hooks test <event> [--tool <name> --input <json> \| --prompt <text>]` | Run an event's hooks on a sample |
| `aristra plugin install <plugin> [-s scope] [--config KEY=VALUE]` | Install a plugin |
| `aristra plugin uninstall`, `enable`, `disable`, `update`, `list`, `prune` | Manage plugins |
| `aristra plugin configure <plugin>` | A plugin's options |
| `aristra plugin validate <path>` | Check a plugin or marketplace |
| `aristra plugin marketplace add <source>`, `list`, `remove <name>`, `update [name]` | Manage marketplaces |

See [MCP servers](/code/extend/mcp), [Hooks](/code/extend/hooks) and [Plugins](/code/extend/plugins).

## Settings

| Command | Does |
|---|---|
| `aristra config get [key] [--json]` | Settings in effect, and where each comes from |
| `aristra config set <key> <value> [--project \| --local]` | Change a setting, in your file or the project's |
| `aristra config edit [--project \| --local]` | Open a settings file in your editor |
| `aristra import <claude-code\|codex>` | Bring your instructions, MCP servers, permission rules, default mode, hooks, skills, agents and commands over from Claude Code or Codex. Shows a preview first. `--yes=<digest>` applies the checked items (yours, not skills), `--only <id>` picks items, including skills and the folder's own, `--dry-run` shows the result, and `--json` prints it as JSON |

## Support

| Command | Does |
|---|---|
| `aristra doctor [--json]` | Check your setup and say how to fix each problem |
| `aristra logs [-n <lines>] [-f]` | The runtime's log |
| `aristra diagnostics export [--no-logs]` | Write a support bundle, with secrets removed, to `~/.aristra/diagnostics/` |

## The runtime

| Command | Does |
|---|---|
| `aristra runtime status [--json]` | Whether the runtime is running, and what it holds. Doesn't start one |
| `aristra runtime stop [--now]` | Stop it once nothing runs; `--now` stops running turns too |
| `aristra tasks [list] [--json]`, `tasks add "<prompt>" --every day\|weekday\|<day> --at <HH:MM>` (or `--every hour --at <minute>`, or `--once "<date> <time>"`), `tasks pause\|resume\|run\|remove <id>` | The scheduled tasks saved on this computer. `add` also takes `--name`, `--folder`, `--source`, `--model`, `--mode`, `--skip-missed` and `--send` (`telegram`, `email` or both, with a plan). See [Scheduled tasks](/code/guides/background#scheduled-tasks) |
| `aristra service install`, `uninstall [--now]`, `status [--json]` | The background service. See [Background work](/code/guides/background#the-background-service) |
| `aristra serve` | Run the runtime yourself (`--socket` or `--stdio`); surfaces start it for you |
| `aristra acp` | Serve an editor over the Agent Client Protocol. See [Editors](/code/editors) |

## Installing

| Command | Does |
|---|---|
| `aristra update [--check]` | Update to the newest release on your channel |
| `aristra install [latest\|stable\|<version>]` | Switch channel or version (default `latest`) |
