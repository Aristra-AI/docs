Aristra Code works in a folder on your computer. Tell it what you want done in plain language: it reads the code it needs, makes the changes across files, runs your tests and commands, and asks before it does anything you have not allowed. It remembers your project's instructions across chats, works with git and pull requests, and runs on the model you choose.

```sh
curl -fsSL https://aristralabs.com/install.sh | sh
cd ~/code/my-project
aristra
```

The first run signs you in to Aristra, asks which model new chats start with, and asks whether you trust the folder. Then you type what you want. The [quickstart](/code/quickstart) walks through a first real task.

## Where it runs

The terminal, Aristra Desktop and your editor talk to the same agent on your computer, the Aristra Runtime, so a chat started in one shows in the others, and any of them can approve its next step. With a plan, Remote Control shares a chat to your phone and the web.

## What you can do

<AccordionGroup>
  <Accordion title="Build features and fix bugs">
    Describe the change, or paste the error. Aristra Code finds the code involved, plans the change, edits the files and runs your tests until they pass.

    ```sh
    aristra "the date parser fails on leap years: find why, fix it, and run the tests"
    ```
  </Accordion>
  <Accordion title="Work with git and pull requests">
    It writes commits, works in its own git worktree when you ask, shows the open pull request's checks and reviews with `/pr`, and can watch a pull request and fix what its checks and reviewers report with `/autofix-pr`. See [Git and pull requests](/code/guides/git).
  </Accordion>
  <Accordion title="Keep work going in the background">
    Long commands move to the background and tell the chat when they end. `/loop` repeats a prompt, scheduled tasks run on a timetable, and `/goal` keeps it working until a condition you set holds. See [Background work](/code/guides/background).
  </Accordion>
  <Accordion title="Connect your tools">
    Add MCP servers, use your Aristra account's connectors, write skills for the work you repeat, run your own commands on events with hooks, and install plugins that bundle all of these. See [Extend](/code/extend/mcp).
  </Accordion>
  <Accordion title="Script it">
    `aristra run` and `aristra -p` run one turn without the app, for scripts and CI, with JSON output. See [Non-interactive mode](/code/non-interactive).
  </Accordion>
</AccordionGroup>

## Your models, your rules

- **Models.** Use Aristra's models from your Aristra balance, at their providers' own prices, your ChatGPT plan, your own provider keys (OpenAI, Anthropic, Gemini, OpenRouter and others) or a model running on your computer. Each chat says who pays. See [Models](/code/configure/models).
- **Free on your computer.** Aristra Code with a model of your own costs nothing. Your account's memory on every device comes with every account. A plan adds what else Aristra hosts: monthly usage of its models, Remote Control, connectors and a cloud computer. Without a plan, chats in the cloud and Aristra's models are paid from your balance, starting with a $1 starter credit, and a cloud computer runs on top-ups. See [Your account and Aristra One](/account/overview).
- **Permissions.** Chats start in Manual mode: reading, searching and commands that only read run on their own, and changes ask first. Accept edits, Plan and Auto are a Shift+Tab away. See [Permissions](/code/configure/permissions).
- **Sandbox.** Off by default. Turn it on with `/sandbox` and commands run in an operating system sandbox that limits what they can write and reach. See [Sandbox](/code/configure/sandbox).
- **Instructions.** An `AGENTS.md` file in your repository tells Aristra Code how your project works, the same file other coding agents read. See [Memory and instructions](/code/guides/memory).
