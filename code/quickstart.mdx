This guide takes you from nothing installed to a first finished change. It uses the terminal; the same chat works in [Aristra Desktop](/code/desktop) too.

<Steps>
  <Step title="Install">
    ```sh
    curl -fsSL https://aristralabs.com/install.sh | sh
    ```

    This installs the newest release for your machine (macOS on Apple silicon or Intel, Linux on x64 or arm64) into your home folder, with no root access. If `~/.local/bin` is not on your `PATH` yet, the installer adds it to your shell profile and says so. Open a new terminal afterwards.

    Check the install:

    ```sh
    aristra --version
    aristra doctor
    ```

    `aristra doctor` checks your setup and marks each line `ok` or `fix`, with how to fix it. On Windows, use WSL2; see [Setup](/code/setup).
  </Step>

  <Step title="Start it in a project">
    ```sh
    cd ~/code/my-project
    aristra
    ```

    The first run asks only what it still needs, one screen at a time:

    1. **Sign in to Aristra.** Every chat needs an Aristra account, including chats on your own keys or on a local model. The account is free: see [what is free and what a plan adds](/account/overview). Press Enter to sign in **In your browser**: your browser opens the sign-in page (if it doesn't, open the link the terminal prints), and you choose **Approve**. Without a browser (over SSH, for example), **With a code, on another device** comes first: open app.aristralabs.com/desktop/device on any device and enter the code. While the browser sign-in waits, press c to switch to a code. Esc skips it, and `/login` signs in later. Every step is in [Sign in](/quickstart#sign-in).
    2. **Choose the model new chats start with.** Each choice says who pays: your Aristra balance, your ChatGPT plan, your own key, or "runs on this computer". Change it any time with `/model`. To use your ChatGPT plan, a key or a local model, see [Set up your model](#set-up-your-model).
    3. **Trust the folder.** Aristra Code reads, edits and runs files in a folder you trust. "No, exit" is selected first; press Down, then Enter, to trust it. The answer is saved for the repository and its subfolders. Your home folder is trusted for this run only.
    4. **New MCP servers.** If the folder's `.mcp.json` has servers you haven't answered yet, it asks which to use. Starting in Bypass permissions shows a warning to accept first.
  </Step>

  <Step title="Ask for a change">
    Type what you want done and press Enter:

    ```text
    › Find why the date parser fails on leap years and fix it. Run the tests when you are done.
    ```

    You will see:
    - The reply stream in as Markdown.
    - Each step as one line: `Read src/date.ts`, `Search for leap`, `Edit src/date.ts`, `$ npm test`.
    - Each edit's diff, and each command's output, cut to a few lines. Ctrl+O opens the newest step's full output.
    - The status line with what it is doing and how full the model's context is, and the footer with the mode, the branch's pull request, the model and who pays.
  </Step>

  <Step title="Approve what it asks">
    New chats start in **Manual** mode: reading, searching and commands that only read run on their own (with the sandbox on, so do commands in it), and other changes ask first. An approval shows the exact command or diff with three answers:

    - **Yes** for this one step.
    - **Yes, and don't ask again** for this kind of step, which saves a rule (or allows edits for the rest of the chat).
    - **No**.

    Press Tab on Yes or No to add a note the model reads.

    Press Shift+Tab to cycle modes: **Accept edits** (edits in the folder run on their own), **Plan** (explore and propose first), **Auto** (Aristra's reviewer decides what would ask) and back to Manual. See [Permissions](/code/configure/permissions).
  </Step>
</Steps>

## Set up your model

Every chat runs on a model from a **source**, and each source says who pays. Aristra's models are ready as soon as you sign in. To use your ChatGPT plan, your own key or a model on your computer, set it up with the steps below, then choose it with `/model`. Whichever you choose, you still sign in to Aristra.

<Tabs>
  <Tab title="Aristra">
    Nothing to set up. Aristra's models are paid from your Aristra balance: a new account's $1 starter credit first, then a plan's monthly usage, then top-ups.

    1. Run `/model` in a chat (or wait for the first-run model step).
    2. Under **Aristra**, choose a model.

    In Aristra Desktop, choose it in the model menu under the message box. See [Models](/code/configure/models#sources) for prices.
  </Tab>

  <Tab title="ChatGPT plan">
    Your ChatGPT subscription supplies the model, and Aristra Code runs the turn with its own tools and approvals.

    **In the terminal**

    1. Run `/model` in a chat.
    2. Under **ChatGPT plan**, choose **Sign in with your ChatGPT plan (a code you enter in a browser)**.
    3. The terminal shows OpenAI's page (`https://auth.openai.com/codex/device`) and a code. Open the page on any device, sign in to ChatGPT and enter the code.
    4. Back in `/model`, choose a ChatGPT model.

    **In Aristra Desktop**

    1. Open **Aristra › Settings…** (⌘,) and choose **Models**.
    2. Under **Accounts**, on **ChatGPT plan**, choose **Sign in with ChatGPT**. Your browser opens OpenAI's page.
    3. Enter the code Settings shows (**Copy** copies it). The code works for 15 minutes.
    4. The row then shows your email and plan.

    A Codex CLI sign-in on the same computer isn't reused. `/usage` shows your plan's 5-hour and weekly limits. To sign out of the plan, run `aristra logout chatgpt` (or `/logout chatgpt` in a chat), or choose **Sign out** on the row in Aristra Desktop; Aristra stays signed in.
  </Tab>

  <Tab title="Your own key">
    Your provider bills you for the model calls. The sources are `openai`, `anthropic`, `gemini`, `openrouter`, `fireworks`, `deepseek`, `xai`, `moonshot`, `zai` and `minimax`.

    **In the terminal**

    1. Run `aristra keys add` with the source, for example:

       ```sh
       aristra keys add anthropic
       ```

    2. Paste the key when asked. It isn't shown as you type.
    3. It says **Saved the Anthropic key**. Check its models with `aristra models --source anthropic`.
    4. In a chat, run `/model` and choose a model under that provider.

    **In Aristra Desktop**

    1. Open **Settings › Models**.
    2. Under **API keys**, open **Add a provider** and choose **Add key** on the provider.
    3. Paste the key and choose **Save**.

    Keys go to Aristra's credential store, never to a settings file, and are sent only to their own provider. `aristra keys list` shows which are set, and `aristra keys remove <source>` removes one.
  </Tab>

  <Tab title="Ollama">
    A model in [Ollama](https://ollama.com) runs on your computer, and nobody pays for its calls.

    **Before you start**

    - Choose a model that can **call tools**: Aristra Code works through tools, so a model without them fails.
    - Aristra needs a context window of at least **16,384 tokens**. Ollama's default is often smaller.
    - Local models work in chats on this computer. Cloud chats (the website, your phone, `aristra --cloud`) use Aristra's models.

    **In the terminal**

    1. Install Ollama from [ollama.com/download](https://ollama.com/download) and start it: open the Ollama app, or run `ollama serve`.
    2. Download a model that can call tools, for example:

       ```sh
       ollama pull qwen3:8b
       ```

    3. Give it at least a 16K context: in the Ollama app's settings, set **Context length** to 16k or more. Or start Ollama with:

       ```sh
       OLLAMA_CONTEXT_LENGTH=16384 ollama serve
       ```

    4. Check that Aristra finds it:

       ```sh
       aristra models --source ollama
       ```

       It lists your models under **Ollama (ollama): runs on this computer**. Each says whether it **fits this computer**, is **tight on memory**, or is **too big for this computer**, with the memory it needs at a 16K window. Pick one that fits.
    5. In a chat, run `/model` and choose the model under **Ollama**. It becomes the default for new chats, and the footer shows **this computer** as who pays. For one chat only, start with `aristra --source ollama -m qwen3:8b`.

    The first turn can take a while: Aristra waits for Ollama to load the model.

    **In Aristra Desktop**

    1. Do steps 1 to 3 above.
    2. Open **Settings › Models**. Under **On this Mac**, **Ollama** shows **Connected** and how many models are installed. If it says **Not running**, start Ollama (or pull a model, if none is installed) and choose **Check again**.
    3. In the **Code** tab, start a new chat, pick a **Folder**, and set **Where it runs** to **On this Mac**.
    4. In the model menu, choose your model under **Ollama**. It shows **Fits**, **Tight fit** or **Too big**.

    To make it the default, choose it in **Settings › Models › Default model**. If Ollama isn't running when you start a chat, the chat starts on the first source that is ready, so check the model menu.

    **Ollama on another address**

    Aristra uses `OLLAMA_HOST` the way Ollama does, else `localhost:11434`. In the terminal, set it before you start `aristra`. If Aristra is already running, run `aristra runtime stop`, then start `aristra` again.
  </Tab>

  <Tab title="LM Studio">
    A model in [LM Studio](https://lmstudio.ai) runs on your computer, and nobody pays for its calls. The same rules as Ollama apply: a model that can **call tools**, at least **16,384 tokens** of context, and chats on this computer only.

    **In the terminal**

    1. Install LM Studio from [lmstudio.ai](https://lmstudio.ai) and download a model that can call tools.
    2. Load the model with a **context length of 16,384 or more**. Aristra checks the window of a loaded model; a model it loads on first use gets LM Studio's own settings.
    3. Start LM Studio's server on its usual port, 1234: from the app, or with `lms server start`. Aristra looks for it at `localhost:1234` only.
    4. Check that Aristra finds it:

       ```sh
       aristra models --source lmstudio
       ```

    5. In a chat, run `/model` and choose the model under **LM Studio**. For one chat only, start with `aristra --source lmstudio -m <model>`.

    **In Aristra Desktop**

    1. Do steps 1 to 3 above.
    2. Open **Settings › Models**. Under **On this Mac**, **LM Studio** shows **Connected**. If it says **Not running**, start the server and choose **Check again**.
    3. In the **Code** tab, start a chat with a **Folder** and **Where it runs** set to **On this Mac**, and choose the model under **LM Studio**.

    LM Studio 0.4 or later also tells Aristra each model's size and window, for the fit labels and the window check.
  </Tab>

  <Tab title="Another server">
    Any server that speaks Chat Completions, Responses or Anthropic's Messages: vLLM, llama.cpp's server, MLX, a company gateway or a proxy. You can set up one at a time.

    **In the terminal**

    1. Start your server, and note its address and model name.
    2. Add it, for a server on this computer with no key:

       ```sh
       aristra keys add custom --url http://localhost:8000/v1 --wire chat_completions --name "My server" --model qwen3-coder --no-key
       ```

       Or run `aristra keys add custom` and answer each question: the address, the API it speaks (`chat_completions`, `responses` or `anthropic`), its model names, a name and its key. A flag you leave out is asked; press Enter for its default.
    3. It says **Saved** with the name and address. Check its models:

       ```sh
       aristra models --source custom
       ```

    4. In a chat, run `/model` and choose the model under your server's name.

    **In Aristra Desktop**

    1. Open **Settings › Models**. Under **On this Mac**, on **Custom endpoint**, choose **Set up**.
    2. Fill in a **Name**, the API it speaks (**Chat Completions**, **Responses** or **Anthropic Messages**), the **Base URL**, and, if needed, the API key and the model ids.
    3. Choose **Save**. The row shows the name and **Connected**.

    **The address**

    - Include the API's path, usually `/v1`, for Chat Completions and Responses. For Anthropic Messages, leave `/v1` out.
    - Use `https://`. Plain `http://` works only for `localhost`, `127.0.0.1` or `::1`, so a server on another machine needs `https://`.
    - The model names you give are used when the server's model list can't be read, and always for Anthropic Messages.
    - It pays as **this computer** when the address is on your computer or network, else as **your key**.

    `aristra keys remove custom` removes the server.
  </Tab>
</Tabs>

### If a local model doesn't work

<AccordionGroup>
  <Accordion title="Ollama is not running on this computer">
    Start Ollama (the app, or `ollama serve`), then try again; in Aristra Desktop, choose **Check again**. For LM Studio, start its server. If Ollama runs on another address, set `OLLAMA_HOST` and restart Aristra (`aristra runtime stop`).
  </Accordion>
  <Accordion title="No models are installed in Ollama yet">
    Download one with `ollama pull`, then choose **Check again** in Aristra Desktop or run `/model` again.
  </Accordion>
  <Accordion title="The context window is too small">
    The turn stops and says the model's window is under 16,384 tokens. In Ollama, set **Context length** to 16k or more in the app's settings, or start it with `OLLAMA_CONTEXT_LENGTH=16384`. In LM Studio, load the model again with a context length of 16k or more.
  </Accordion>
  <Accordion title="The server returns an error on the first message">
    Often the model can't call tools. Choose a model that can, and check the server's own log.
  </Accordion>
  <Accordion title="Use an https:// address, or http:// for a server on this computer">
    A custom server on another machine needs `https://`. On this computer, use `localhost` or `127.0.0.1` in the address.
  </Accordion>
  <Accordion title="The chat runs on another model">
    In Aristra Desktop, a chat whose default source isn't ready starts on the first one that is. Start the local server, choose **Check again**, and pick the model in the model menu. A chat in the cloud always uses Aristra's models.
  </Accordion>
</AccordionGroup>

## Everyday use

| You want to | Do this |
|---|---|
| Start in this folder | `aristra` |
| Start with a prompt | `aristra "explain the build system"` |
| Continue this folder's newest chat | `aristra -c` |
| Go back to an earlier chat | `aristra resume`, or `/resume` in a chat |
| Open a chat running elsewhere | `aristra attach <id>` |
| Run one turn in a script or CI | `aristra run "fix the lint errors" -o json` |
| See this folder's chats | `aristra sessions` (`--all` for every folder) |
| Choose another model | `/model`, or `aristra models` to list them |
| Add a provider key | `aristra keys add openai` (or `anthropic`, `gemini`, `openrouter`) |
| Change a setting | `aristra config set permissions.defaultMode acceptEdits` |
| Bring your Claude Code or Codex setup | `aristra import claude-code` (or `codex`), with a preview first |
| Check your setup | `aristra doctor` |

In a chat, `/help` lists every command and key.
