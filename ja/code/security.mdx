## コンピューターの外に送られるもの

コンピューター上のチャットは `~/.aristra` に保存されます。外部に送られるものとその送信先は次のとおりです。

| 内容 | 送信先 | タイミング |
|---|---|---|
| モデルの呼び出し（会話と提供するツール） | チャットのソース。Aristra、OpenAI（ChatGPT のプラン）、自分のキーのプロバイダー、カスタムエンドポイント。コンピューター上のモデルなら何も送信されません | モデルを呼び出すたび |
| プロフィール（名前、職業、**About you** のメモ） | Aristra から読み込みます | チャットのターンで、最大 10 分に 1 回 |
| このフォルダーに関するアカウントのメモリ | Aristra から読み込みます。リポジトリのリモートとフォルダーの名前でタグ付けされ、パスは使われません | メモリがオンのチャットのターン |
| Aristra Code がメモリに保存する内容と、リポジトリのメモ | Aristra | 保存したとき |
| ウェブ検索 | Aristra の検索、または自分のキーを使う Brave | 検索するとき |
| Aristra の検索を使えない場合の検索語 | Exa、Parallel、Firecrawl、Keenable のいずれかの無料の公開検索 | `web.keylessFallback` が `false` でない限り |
| コネクターの呼び出し | 呼び出しを実行する Aristra | アカウントに接続したアプリをチャットが使うとき |
| 追加した MCP サーバーへの呼び出し | そのサーバー | チャットがそのサーバーを使うとき |
| コマンドをクラウドのサンドボックスで実行する場合の、フォルダーのファイル | Aristra のサンドボックスまたは E2B | そうすることを選んだ場合のみ |
| ウェブページ | コンピューターから直接取得します | ページを読むとき |
| Auto モードのレビュアーが確認するステップ | Aristra のレビュアー、または自分のモデル | Auto モードで、本来なら確認を求めるもの |
| 内容を含まない利用イベントとエラーレポート | Aristra | オフにしない限り |
| 共有したチャット、またはクラウドチャットからこのコンピューターのフォルダーへの呼び出し | Aristra | チャットを共有したか、フォルダーを接続した場合のみ |
| Aristra Code が送ってくるファイル | Aristra | スマートフォンやウェブにファイルを送るとき |
| スケジュールタスクの結果 | Aristra 経由で Telegram またはメールへ | 結果を送るよう設定したタスクのみ |
| プルリクエストのステータス、`/pr`、自動修正 | GitHub または GitLab。自分の `gh` か `glab` のログインを使います | プルリクエストのあるブランチで |
| プラグインのカタログとプラグイン | 追加したマーケットプレイス（既定では GitHub 上の Anthropic のもの） | マーケットプレイスを追加または更新するとき、プラグインをインストールするとき |

Aristra のモデルの呼び出しは、Aristra のサーバーを経由してモデルのプロバイダーに渡され、アカウントで使用量が計測されます。その呼び出しによって、会話の内容が保存されることはありません。

### プランの有無による違い

サインインしていれば、プランの有無にかかわらず、Aristra が覚えているあなたのことは Aristra のアカウントに保存されます。そのため、ウェブ、スマートフォン、他のコンピューターにも引き継がれます。

| | プランあり | プランなし |
|---|---|---|
| チャットのトランスクリプト | このコンピューター上。アップロードされることはありません | 同じ |
| ウェブに共有したチャット | そのターンがチャットとしてアカウントに保存され、**Search and reference past chats** で見つけられます | 使えません |
| Aristra が覚えているあなたのこと | アカウントのメモリ。各ターンで読み込まれ、メモリツールで書き込まれるため、このコンピューターの外に送られます | 同じ |
| リポジトリのメモ | このコンピューター上のファイル。アカウントに一方向でコピーされます | 同じ |
| ファイル | アカウントにコピーを保存しない限り、このコンピューター上 | 同じ |

サインアウトしている間、Aristra はあなたについて何も覚えません。メモリがすべてのアカウントに含まれるようになる前にファイルでメモリを保持していたコンピューターは、サインインした状態で初めてチャットを始めたときに、それらのメモをアカウントに一度だけ送ります。

## サインイン

`aristra login`（または初回の実行）は、ブラウザーで、または任意のデバイスで入力するコード（SSH 経由や `--device-code` の場合）で、このコンピューターを Aristra アカウントのデバイスとして追加します。このとき、次のものが作成されます。

- アカウント上の**デバイス**。ウェブサイトのデバイスの一覧に表示され、そこで取り消せます。
- **デバイスキー**。Mac では Secure Enclave で作成されるため、チップの外にコピーすることはできません。Linux では、認証情報ストアに保存されるソフトウェアキーです。サインインの更新はすべてこのキーで署名されるため、盗まれたトークンを別の場所で使うことはできません。Secure Enclave のない Mac（T2 チップのない Intel Mac、仮想マシン）は、デバイスキーなしでサインインします。
- **トークン**。有効期間 15 分のアクセストークンと、有効期間 30 日のリフレッシュトークンで、認証情報ストアに保存されます。

`aristra logout` はこのコンピューターでサインアウトし、デバイスを取り消します。ウェブサイトからデバイスをサインアウトしても、デバイスは取り消されます。

## シークレットの保存場所

プロバイダーキー、MCP のシークレット、すべてのサインイン情報は、Aristra の認証情報ストアに保存され、設定ファイルに書き込まれることはありません。**サーフェスはシークレットを書き込めますが、読み出すことはできません**。ストアはキーチェーンのキーで暗号化されています。承認したコマンドは自分のアクセス権で実行されるため、ストアにアクセスできる可能性があります。エージェントのツールとサンドボックス内のコマンドを近づけないようにするには、権限に `"deny": ["read(~/.aristra/**)"]` を追加してください。

| ストア | 場所 |
|---|---|
| macOS のキーチェーン | `~/.aristra/credentials.enc`。ログインキーチェーンに保存されたランダムなキーで暗号化されます |
| Linux のキーリング | 同じ暗号化されたファイルで、キーは Secret Service に保存されます |
| ファイル | `~/.aristra/credentials.json`（自分だけが読めます）。応答するキーチェーンがない場合（Linux では `secret-tool` がインストールされていない場合も）に使われます。`ARISTRA_CREDENTIALS_STORE` は `credentials.store` より優先されます |

`credentials.store`（`auto`、`keychain`、`file`）で選びます。どれが使われているかは `aristra doctor` で確認できます。

## Aristra Code を閉じ込めるしくみ

| 脅威 | 防ぐもの |
|---|---|
| ウェブページ、ファイル、ツールの出力が、エージェントに有害なことをさせようとする | 権限のチェックとサンドボックス。外部のコンテンツは、信頼できないという印付きでモデルに届きます。Auto モードのレビュアーがツールの結果を見ることはありません |
| コマンドがネットワークに接続しようとしたり、フォルダーの外に書き込もうとしたりする | 読み取り以上のことをするすべてのコマンドに対する承認と、オンにした場合は[サンドボックス](/ja/code/configure/sandbox)。ネットワークはプロキシを経由して許可したホストにだけ接続でき、書き込みはチャットのフォルダー内に限られます |
| 悪意のある MCP サーバー | まずパッケージが既知のマルウェアと照合され、信頼するまでツールは確認を求め、`"sandbox": true` でサンドボックス内で実行されます |
| リポジトリの設定がすべてを許可しようとする | フォルダーのルール、モード、サンドボックスの設定は、信頼したあとでだけ有効になり、その `.mcp.json` のサーバーは起動の前に確認を求めます。レビュアー、シークレットの保存場所、サイドモデルは、自分の設定からしか読み込まれません |
| エージェントがリポジトリの設定やエージェント用のファイルを編集する | `.aristra`、`.claude`、`.git`、`.vscode`、`.idea`、シェルの起動ファイル、`.mcp.json` への変更は、ルールだけでは決して実行されません。どのモードでも確認を求め、Auto ではレビュアーが判断します |
| シークレットがログに漏れる | シークレットのように見える値は、ツールの結果、イベント、ログ、エクスポートでマスクされます |
| ノートパソコンの盗難 | シークレットはログインキーチェーンのキーで暗号化され、サインインはデバイスキーに結び付けられています。ウェブサイトでデバイスを取り消してください |

<Tip>
サンドボックスでは、既定で読み取りが開放されています。認証情報のフォルダーは拒否ルールで閉じてください：`"deny": ["read(~/.ssh/**)", "read(~/.aws/**)"]`。
</Tip>

ランタイムとやり取りできるのは自分のユーザーだけです。ランタイムは、自分のユーザーアカウントと照合されるプライベートなソケットで待ち受け、ネットワークで待ち受けることはありません。

## ログ

ランタイムは `~/.aristra/logs/runtime.log` にログを書き込みます。シークレットはマスクされ、7 日間保持されます。`aristra logs` で読み、`aristra logs -f` で追いかけ、`ARISTRA_LOG_LEVEL` で出力の詳しさを設定します。

`aristra diagnostics export` は、`~/.aristra/diagnostics/` にサポート用のバンドルを書き出します。バージョン、チェックの結果、自分の設定ファイル、テーブルのサイズ（メッセージは含みません）、ログが含まれ、改めてマスクされたうえでメールアドレスが取り除かれます。何も送信しないので、共有する前に中身を確認してください。

## テレメトリー

Aristra Code は、内容を含まない利用イベントとエラーレポートを送信します。プロンプト、返信、コード、コマンド、ファイルの内容、ファイルやフォルダーの名前、パス、URL、MCP サーバーの名前、エラーメッセージが送信されることはありません。すべての値は、カテゴリ、件数、所要時間、時刻、またはモデル名のような固定の一覧にある識別子です。サインアウトしている間は何も送信されず、送信できなかったイベントは破棄され、ディスクに書き込まれることはありません。

| オフにする方法 | 利用イベント | エラーレポート |
|---|---|---|
| 設定 | `telemetry.usage: false` | `telemetry.errors: false` |
| 環境変数 | `ARISTRA_DISABLE_TELEMETRY=1` | `ARISTRA_DISABLE_ERROR_REPORTING=1` |
| 両方 | `ARISTRA_DISABLE_NONESSENTIAL_TRAFFIC=1` | |
| Aristra Desktop | Settings › General › Privacy › **Share usage data** | **Send error reports** |

環境変数はランタイムの起動時に読み込まれます。設定したあとは `aristra runtime stop` を実行してください。それぞれがオンかどうかは `aristra doctor` で確認できます。
