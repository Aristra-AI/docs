スキルは、ある種類のタスクのための指示をまとめたものです。チームのリリースノートの書き方、ホットフィックスの切り方、マイグレーションをレビューするためのチェックリストなどです。Claude Code と同じ形式の `SKILL.md` ファイルなので、両者の間でスキルを移せます。Claude Code のその他のフィールド（`allowed-tools`、`model`、`context`、`agent`、`hooks`、`paths`、`shell`）は無視されます。これらを使うスキルも、それらのフィールドなしで読み込まれます。

## スキルの保存場所

| 場所 | 使われるチャット |
|---|---|
| `~/.aristra/skills/<name>/SKILL.md` | すべてのチャット |
| `<folder>/.aristra/skills/<name>/SKILL.md` | そのフォルダーのチャット。フォルダーを信頼したあとで使われます |
| [プラグイン](/ja/code/extend/plugins) | すべてのチャット。`plugin-name:skill-name` として使われます |

スキルのフォルダーには、`SKILL.md` の横に、スキルが Aristra Code に参照させる他のファイル（テンプレート、スクリプト、例）を置けます。Claude Code のスキルを使うには、そのフォルダーを `~/.claude/skills/` から `~/.aristra/skills/` にコピーするか（リンクしたフォルダーはスキップされます）、`aristra import claude-code` を実行して、使いたいスキルを `--only` で指定します。スキルは既定の取り込み対象には含まれていないためです。

## スキルを書く

```markdown ~/.aristra/skills/release-notes/SKILL.md
---
name: release-notes
description: Write release notes from the merged pull requests since the last tag
when_to_use: When the user asks for release notes or a changelog entry
argument-hint: "[version]"
---

1. Find the last tag with `git describe --tags --abbrev=0`.
2. List the merged pull requests since then with `git log <tag>..HEAD --merges --oneline`.
3. Group them under Added, Changed and Fixed, one line each, in the past tense.
4. Title the notes "Release $ARGUMENTS". Use the template in ${ARISTRA_SKILL_DIR}/template.md.
```

| フィールド | 意味 |
|---|---|
| `name` | 表示名。入力するのはフォルダーの名前です。`skills/release-notes/` なら `/release-notes` |
| `description` | スキルが何をするか。モデルに表示されます |
| `when_to_use` | いつ使うか。モデルが見る内容に追加されます |
| `argument-hint` | `/name` のあとに入力するもの。コマンドメニューに表示されます |
| `user-invocable` | `false` にすると `/` メニューに表示されません（モデルは引き続き使えます） |
| `disable-model-invocation` | `true` にするとモデルからは使えなくなります（`/name` と入力すれば使えます） |

本文では、`$ARGUMENTS` は `/name` のあとに入力したものすべて、`$1` から `$9` はその各語、`${ARISTRA_SKILL_DIR}` はスキルのフォルダーを表します。

## スキルが使われるしくみ

- **Aristra Code が使う**：各ターンで、モデルはスキルの名前と説明を見ます。タスクに合うスキルがあれば、その指示全体を読み込みます。
- **自分で使う**：`/` を入力してスキルを選ぶか、`/release-notes 2.4.0` のように入力します。スキルの指示が、`2.4.0` を引数として送られます。

`/help` では、コマンドの下にスキルが一覧表示されます。保存した[ワークフロー](/ja/code/guides/subagents)と MCP サーバーのプロンプトも同じメニューに表示されます。

## 組み込みのスキル

| スキル | 動作 | Aristra Code が自分の判断で使えるか |
|---|---|---|
| `/init` | コードからフォルダーの `AGENTS.md` を書きます | いいえ |
| `/code-review [level] [target]`（または `/review`） | 現在の差分、プルリクエスト、ブランチ、パスを対象に、バグと整理すべき点を深刻なものから順にレビューします | はい |
| `/simplify [target]` | 動作を変えずに、変更したコードを整理します | はい |
| `/security-review` | ブランチの変更のセキュリティレビュー。実際に悪用される可能性の高い脆弱性だけを報告します | はい |
| `/update-config [request]` | 設定を変更します。権限のルール、フック、サンドボックス、MCP サーバー | はい |
| `/fewer-permission-prompts` | よく承認している読み取り専用のコマンドと MCP ツールを、フォルダーの許可リストに追加します | はい |
| `/debug [issue]` | Aristra のログを読んで、何が問題だったかを探します | いいえ |
| `/verify [what to check]` | 変更したアプリを実行し、変更が機能するかを確認して、PASS、FAIL、BLOCKED、SKIP のいずれかを報告します | いいえ |
| `/commit [guidance]` | フックのスキップ、amend、シークレットのコミットをせずに、リポジトリのスタイルのメッセージで変更をコミットします | いいえ |
| `/create-pr [--draft]` | コミットしてプッシュし、プルリクエストを作成します | いいえ |
| `/loop [interval] [prompt]`（または `/proactive`） | プロンプトかコマンドを一定の間隔で、または自分でペースを決めて実行します。[バックグラウンド処理](/ja/code/guides/background)を参照してください | はい |
| `/workflow-authoring` | [ワークフロー](/ja/code/guides/subagents)のスクリプトを書くための完全なリファレンス | はい |

`/code-review` にはレベルを指定できます。`low`（すばやく 1 回）、`medium`（最初の既定）、`high`、`xhigh`、`max`（最も徹底的）です。指定しない場合は、このチャットで最後に指定したレベルを使います。`--fix` で指摘を適用し、`--comment` でプルリクエストに投稿し、`--max-findings <n>`（または `all`）で報告する件数を設定します。

`init` や `security-review` という名前の自分のスキルを作ると、組み込みのスキルが置き換えられます。

## 信頼

フォルダーのスキルは、フォルダーを信頼したあとでだけ有効になります。そのため、クローンしたばかりのリポジトリが Aristra Code に指示を差し込むことはできません。
