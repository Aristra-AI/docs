サブコマンドを付けずに `aristra` を実行すると、現在のフォルダーで Aristra Code が開きます。

```sh
aristra                          # a new chat in this folder
aristra "add a --verbose flag"   # a new chat that starts with this prompt
aristra -c                       # this folder's newest chat
aristra -r <id>                  # that chat
aristra resume                   # pick an earlier chat
aristra attach <id>              # a chat that may be running elsewhere
aristra --fullscreen             # draw on the whole screen
aristra --folder ~/code/api      # work in another folder
aristra --cloud "plan the launch"   # a chat run by Aristra's cloud agent
```

すべてのオプションは [CLI リファレンス](/ja/code/reference/cli)にあります。

## 画面

```text
aristra · gemini-3.8-flash · Aristra balance · /Users/you/code/my-project · Manual  the header

› Find why the date parser fails on leap years and fix it.                          your message
● Searched for 1 pattern, read 2 files                                              reads and searches, one line
● Edit src/date.ts                                                                  an edit, with its diff
  npm test                                                                          a command, with its output
The parser treated 1900 as a leap year. ...                                         the reply

╭──────────────────────────────────────────────────────────────────────────────╮
│ ›                                                                            │  the composer
╰──────────────────────────────────────────────────────────────────────────────╯
 ⠋ Working 12 s · esc to interrupt                              ████░░░░░░ 41% of the window
 Manual · asks before changes the rules do not allow (shift+tab)    gemini-3.8-flash · Aristra balance
```

- **ステップ**：各ツールの呼び出しは、実行内容を示す 1 行で表示されます。連続した読み取りと検索は 1 行にまとめられます。編集では差分が、コマンドでは出力の先頭が表示されます。**Ctrl+O** で最新のステップの出力全体を開けます。
- **タスクリスト**：エージェントがタスクリストを管理しているときは、入力欄の上に表示されます。**Ctrl+T** で表示と非表示を切り替えます。
- **ステータス行**：エージェントが実行していること、バックグラウンドで動いているもの（`/tasks` で一覧表示）、他のチャットで待機中の承認の数、モデルのコンテキストの使用状況（60% で黄色、80% で赤。上限が近づくと、自動圧縮までの残りを表示）を示します。`/usage` で使用したトークンを確認できます。
- **フッター**：モード、ブランチで開いているプルリクエスト（`PR #412`。レビューの状態に応じて色分け）、モデル、支払い元を表示します。
- **候補**：何回か返信があったあと、空の入力欄に次のメッセージの候補がグレーで表示されることがあります。Tab キーで採用、Enter キーで送信でき、入力を始めると無視されます。

## キー操作

| キー | 動作 |
|---|---|
| Enter | 送信します。ターンの実行中は、次のステップでメッセージをそのターンに追加します |
| Shift+Enter、Alt+Enter、Ctrl+J、または `\` のあとに Enter | 改行します（ターミナルで Shift+Enter が効かない場合は `/terminal-setup` を実行します） |
| Esc | 実行中のターンを停止します。空の入力欄で 2 回押すと、以前のメッセージに戻ります |
| Shift+Tab | モードを順に切り替えます：Manual、Accept edits、Plan、Auto（bypass 用のフラグを付けて起動した場合は Plan のあとに Bypass Permissions。クラウドチャットでは Manual と Auto） |
| 先頭の `!` | シェルモード。自分でコマンドを実行します |
| `@` | ファイルやフォルダーをメンションします。Tab キーで補完します |
| `/` | コマンドと自分のスキル |
| Ctrl+V | クリップボードの画像を添付します |
| Ctrl+O | 最新のステップの出力全体 |
| Alt+P | モデルを選びます |
| Ctrl+L | 画面をクリアします |
| Ctrl+X のあとに Tab | フルスクリーンで差分パネルが開いているときに、キー操作をパネルに渡します（Esc で戻します） |
| Ctrl+Up、Ctrl+Down（または Alt+Up、Alt+Down） | フルスクリーンで、差分パネルのファイル間を移動します |
| Ctrl+T | タスクリストの表示と非表示を切り替えます |
| コマンドの実行中に Ctrl+B | コマンドをバックグラウンドに移します（tmux では Ctrl+B を 2 回） |
| Ctrl+R | 以前のプロンプトを検索します |
| Ctrl+G | 下書きをエディターで編集します |
| Ctrl+S | 下書きを一時退避します。空の入力欄でもう一度押すと元に戻ります |
| Up、Down | 以前のプロンプト。このフォルダーのものが先に表示されます |
| Ctrl+C | 入力欄をクリアします。空の入力欄で 2 回押すと終了します |

キーの割り当ては `~/.aristra/keybindings.json` で変更できます（`/keybindings` で開きます）。[ターミナルの設定](/ja/code/configure/terminal)を参照してください。

## ターンの実行中にメッセージを送る

Aristra Code が 1 つのチャットで一度に実行するターンは 1 つです。ターンの実行中は、次のように動作します。

- **Enter キーで指示を送ります**。メッセージは、次のステップで実行中のターンに加わります。停止せずに方向を修正したいときに使います。
- **`/queue <message>` は待機し**、実行中のターンが終わったあとに新しいターンとして送られます。
- **Esc キーで停止します**。実行中のコマンドとフックは、それらが起動したものもすべて含めて停止し、待機中の承認はキャンセルされます。そのあと Aristra Code が、代わりに何をするかを尋ねます。

## 承認

ステップに回答が必要になると、入力欄の上に表示されます。ステップの種類、実際に行われること（コマンド、差分、アドレス）、回答の選択肢が表示されます。

| 回答 | 意味 |
|---|---|
| Yes | このステップを実行します |
| Yes, and don't ask again for `rule` | 実行し、ルールをフォルダーの `.aristra/settings.local.json` に保存します。コマンドの場合は、先にルールを編集できます |
| Yes, and switch to accept edits | 実行し、チャットの残りの間、確認なしでファイルを編集できるようにします |
| Yes, allow reading from `X/` | 実行し、チャットがそのフォルダーを読めるようにします |
| No | 実行せずにターンを停止します。Yes か No で Tab キーを押すとメモを追加できます。No の場合、モデルはメモを理由として読み、作業を続けます |

数字キーを押すか、選択肢を移動して Enter キーを押します。コマンドで **Ctrl+E** を押すと、そのコマンドが何をするのか、なぜ実行するのか、どんなリスクがあるのかが説明されます。

**プランモードの承認**では、計画が表示され、先に進むかどうかを尋ねられます。選択肢は、Auto モードで進める（Auto がオフの場合は編集を自動で承諾して進める）、編集を手動で承認しながら進める、「Tell Aristra what to change」で計画を続ける、のいずれかです。Shift+Tab を押すと、入力した内容で承認します。**Ctrl+G** で計画をエディターで開けます。

承認は開いているすべてのサーフェスに表示され、最初の回答が採用されます。回答がないまま 30 分経つと拒否されます（`approvals.timeoutMinutes`）。

## モデルを選ぶ

`/model` を実行すると、すべてのモデルのソースが支払い元とともに一覧表示されます。準備ができていないソースには、設定方法が表示されます。モデルを選ぶと、このチャットのモデルが切り替わり、新しいチャットの既定にもなります。`/effort` で、モデルがどの程度深く考えるかを設定します。[モデル](/ja/code/configure/models)を参照してください。

## 再開する

`/resume`（または `aristra resume`）を実行すると、ターミナル、Aristra Desktop、スクリプト、エディターなど、すべてのサーフェスのチャットが一覧表示されます。入力すると検索でき、Tab キーでこのフォルダーとすべてのフォルダーを切り替え、右矢印キーでプレビューし、Enter キーで開きます。まだ実行中のチャットは、開いても実行を続けます。

## 以前のメッセージに戻る

`/rewind` を実行するか、空の入力欄で Esc キーを 2 回押すと、自分のメッセージが、各ターンで変更された内容とともに一覧表示されます。1 つ選んでから、次のいずれかを選びます。

| 選択肢 | 動作 |
|---|---|
| Restore code and conversation | 下の 2 つの両方を行います |
| Restore conversation | そのメッセージとそれ以降がチャットから外れ、メッセージが入力欄に戻るので、編集して送り直せます |
| Restore code | エージェントがファイルツールで変更したファイルを、そのメッセージの前の状態に戻します |

コマンドや自分自身が行った変更は元に戻りません。[チャット](/ja/code/guides/chats)を参照してください。

## 自分でコマンドを実行する

入力欄の先頭に `!` を入力すると、Enter キーでコマンドがチャットのフォルダーで、自分のユーザーとして、サンドボックスの外で実行されます。ただし、サンドボックスがオンで、コマンドがサンドボックスの外に出られない設定（自分の設定かチームの[ポリシー](/ja/code/configure/managed-policy)で `sandbox.allowUnsandboxedCommands: false`）の場合は、除外されたコマンドでない限りサンドボックス内で実行されます。ターンの実行中は、ターンが終わるまで待機します。コマンドとその出力はステップとして表示され、エージェントは次のメッセージとともにそれを読みます。先頭で Esc キーか Backspace キーを押すと、シェルモードを抜けます。

## 添付

- 長い貼り付けは、短いプレースホルダーの裏にそのまま保持されます。
- ターミナルにドラッグしたファイルは、入力されるのではなく添付されます。画像は、モデルが受け付ける場合にモデルに渡されます。
- `@path` で、メッセージとともにファイルをエージェントに渡します。`@app.py#L10-20` では一部の行を渡します。`.env` などの認証情報のファイルは除外されます。

## 終了する

`/exit`（または `/quit`）、空の入力欄で Ctrl+D、または Ctrl+C を 2 回押します。まだ作業が実行中の場合、Aristra Code は、停止するか、バックグラウンドに移して終了するか、とどまるかを尋ねます。バックグラウンドの作業はランタイムで実行を続け、`aristra resume <id>` で戻れます。

## 通知と要約

しばらくターミナルを操作していないときに、承認が待機したりターンが終了したりすると、Aristra Code がターミナルを通じて通知します（iTerm2、kitty、Ghostty、Apple のターミナルで動作）。`ARISTRA_NO_NOTIFY=1` でオフにできます。

離れていたチャットに戻ると、ゴール、現在のタスク、次のステップをまとめた 1 行の要約が表示されます。`/recap` ですぐに作成でき、`awaySummaryEnabled: false` でオフにできます。

## フルスクリーン

フルスクリーンレンダラーは画面全体を使って描画します。上部にスクロールできるトランスクリプト、下部に入力欄があり、マウスでの選択と差分用のサイドパネルを使えます。`/tui fullscreen`（設定に保存されます）でオンにするか、1 回の起動だけなら `--fullscreen` を使います。`/tui default` で元に戻ります。

フルスクリーンでは、次の操作ができます。
- PgUp と PgDn で半画面ずつスクロールし、Ctrl+Home と Ctrl+End で先頭と末尾に移動します。マウスホイールでもスクロールできます。
- ドラッグして選択すると、離したときにコピーされます（`copyOnSelect: false` でオフにできます）。ターミナル自体の選択を使うには、Shift キー（iTerm2 と Mac の VS Code では Option キー、Apple のターミナルでは Fn キー）を押したまま操作します。
- **Ctrl+O** でトランスクリプト画面が開きます。すべてのステップが出力全体とともに表示され、`/` で検索できます。
- **`/diff`** で、変更されたファイルをトランスクリプトの横に表示します。[Git とプルリクエスト](/ja/code/guides/git)を参照してください。
