Aristra Code は、ツールを呼び出すたびに、その前に、実行するか、確認を求めるか、Auto モードのレビュアーに回すか、拒否するかを決めます。1 つのルールのセットがすべてのサーフェスについて判断するため、ルールはターミナル、Aristra Desktop、スクリプト、エディターのどこでも同じ意味を持ちます。

承認は安全のための確認です。既定でオフの[サンドボックス](/ja/code/configure/sandbox)は、オンにするとセキュリティの境界になります。サンドボックス内のコマンドはチャットのフォルダーの外に書き込めず、許可したホストにしか接続できないため、ルールで別の指定がない限り、確認なしで実行されます。

## モード

| モード | 自動で実行されるもの | それ以外のもの |
|---|---|---|
| **Manual**（`default`） | チャットのフォルダー内での読み取り、検索、一覧表示、読み取りだけのコマンド、サンドボックスがオンならサンドボックス内のコマンド、許可ルールの対象 | 確認を求めます |
| **Accept edits** | 上記に加え、チャットのフォルダー内でのファイルの編集と、そこでの `mkdir`、`touch`、`rm`、`rmdir`、`mv`、`cp`、`sed` | 確認を求めます |
| **Plan** | Manual と同じ。Aristra Code は調査して計画を書き、承認するまで何も変更しません。Bypass permissions を使えるチャットでは、プランモードは Bypass と同じくすべてを実行させます | 確認を求めます |
| **Auto** | Accept edits と同じ。ただし、インタープリターやランナーに対する許可ルール（`shell(python:*)`、`shell(npm run:*)` など）は適用されず、それらのコマンドはレビュアーに回されます | 確認を求める代わりに Auto モードのレビュアーに回されます |
| **Don't ask**（`dontAsk`） | Manual と同じ | 拒否されます |
| **Bypass permissions** | 拒否ルールや確認ルールの対象、安全性のチェック、常にあなたの確認が必要なツールを除くすべて | |
| **Read only** | 読み取り、検索、一覧表示 | 拒否されます。何も変更されません |

**切り替え**は、Shift+Tab（Manual、Accept edits、Plan、チャットで使える場合は Bypass permissions、そして Auto の順）か `/mode <name>` で行います。切り替えは次のツールの呼び出しから適用され、すでに待機中の承認も改めて確認されます。新しいモードで許可されるものは実行されます。

**開始時のモード**は、`--permission-mode`、なければ設定の `permissions.defaultMode`、それもなければ Manual です。

**モードをオフにする**：`permissions.disableAutoMode: "disable"` で Auto をオフにします。Bypass permissions は、`--dangerously-skip-permissions`、`--allow-dangerously-skip-permissions`、`--permission-mode bypassPermissions` のいずれかで始めたチャットでのみ使え、初回に警告が表示され、root では（`IS_SANDBOX=1` でない限り）拒否されます。また、[管理ポリシー](/ja/code/configure/managed-policy)でオフにできます。Aristra Desktop では提供されていません。

## ルール

ルールは `tool` または `tool(specifier)` の形式です。Claude Code のツール名も使えます（`Bash(npm test:*)`、`Read`、`Edit`、`WebFetch`）。

| ルール | 対象 | 指定子 |
|---|---|---|
| `shell` | コマンド | 正確なコマンド、それらの語で始まるコマンドなら `prefix:*`（`shell(npm run:*)`）、またはワイルドカードの `*`（`shell(git log *)`） |
| `read` | ファイルの読み取り、一覧表示、検索 | パスのパターン |
| `edit` | ファイルの編集と書き込み | パスのパターン |
| `web_fetch` | ページの取得と、サンドボックスのネットワーク | `domain:example.com` |
| `mcp__server` | MCP サーバーのツール | すべてなら `mcp__server`、1 つなら `mcp__server__tool` |
| `memory`、`browser`、`mcp` | すべてのメモリツール、両方のブラウザー、すべての MCP ツール | なし |
| `workflow` | 保存したワークフロー | その名前 |
| その他のツール名 | そのツール | なし |

```json .aristra/settings.json
{
  "permissions": {
    "defaultMode": "default",
    "allow": ["shell(npm test:*)", "shell(git diff:*)", "edit(/src/**)"],
    "ask": ["shell(git push:*)"],
    "deny": ["read(~/.env*)", "web_fetch(domain:pastebin.com)"],
    "additionalDirectories": ["../shared"]
  }
}
```

- **パスのパターン**は gitignore の形式です。`//abs/path` はルートから、`~/path` はホームフォルダーから、`/path` はプロジェクトの設定ではプロジェクトのフォルダーから、自分の設定では `~/.aristra` から、それ以外はチャットのフォルダーからのパスです。`**` はフォルダーをまたぎますが、`*` はまたぎません。
- **複合コマンド**（`;`、`&&`、`|`、リダイレクト）：許可ルールは各部分をすべて対象にする必要があります。拒否ルールや確認ルールは、どこか 1 つの部分に一致すれば十分です。`timeout` や `nohup` などのラッパーは、中身を見て判断します。
- **どこかに拒否があれば、どこかにある許可より優先されます。**

`aristra doctor` と `/config` は、読み取れないルールや決して適用されないルールを指摘します。

### ルールの出どころ

| 出どころ | 場所 |
|---|---|
| 管理ポリシー | 管理者が設定します。その拒否ルールは何よりも優先されます |
| 自分 | `~/.aristra/settings.json` |
| 自分（1 つのフォルダー用） | `~/.aristra/settings.json` の `projects` |
| プロジェクト（共有） | `<folder>/.aristra/settings.json`。リポジトリとともにコミットします |
| プロジェクト（自分用） | `<folder>/.aristra/settings.local.json`。「don't ask again」はここに保存されます |
| 1 回の実行 | `aristra run --allow`、`--deny`、`--settings` |
| スキル | スキルの実行中に、スキルが許可するツール |
| 1 つのチャット | 「during this session」の回答と `/add-dir` |

`/permissions` では、すべてのルールが出どころごとに一覧表示され、ルールの追加や削除ができ、チャットのフォルダーが表示され、Auto のレビュアーが最近ブロックしたステップが一覧表示されます。

## フォルダーを信頼する

リポジトリの設定は、それを作った人が書いたものです。フォルダーで最初のチャットを始める前に、Aristra Code はそのフォルダーを信頼するかどうかを尋ねます。最初は「No, exit」が選択されています。信頼すると、その回答はリポジトリとそのサブフォルダーについて保存されます。フォルダーを信頼するまでは、その拒否ルールと確認ルールだけが有効で、スキルとフックは無視されます。`/folder` で、現在のフォルダーが信頼されているかどうかを確認できます。

## 安全性のチェック

一部の変更は、Bypass を含むすべてのモードで確認を求め、どの許可ルールでも通過させられません。Auto では、1 つ目の種類はレビュアーが判断しますが、それ以外はレビュアーが承認することはできません。

- `.git`、`.vscode`、`.idea`、`.claude`、`.aristra` の各フォルダーへの書き込みと、`.gitconfig`、`.gitmodules`、シェルの起動ファイル、`.ripgreprc`、`.mcp.json`、`.claude.json` への書き込み（`.aristra/worktrees` にあるエージェントのワークツリーは保護対象外です）。
- 危険な `rm` と `rmdir` のコマンド。対象が空または未設定の変数のもの、コマンドの出力に対する再帰的な `rm`、ルート、ホーム、最上位のフォルダー、チャットのフォルダーまたはその上位のフォルダー、マウントされたドライブ（`/Volumes`、`/mnt`、`/media`）に対する、再帰的な、またはグロブを使った `rm`、`cd` のあとの相対パスのグロブ、そして `sh -c` のスクリプト内で、実行時にならないと対象がわからない `rm` です。
- チャットを自分以外のワークツリーに移すこと。
- プランモードを抜ける、支払いをするなど、常にあなたの確認が必要なツール。

## 承認

呼び出しが確認を求めると、開いているすべてのサーフェスに、実行される内容と確認を求める理由が表示されます。最初の回答が採用されます。

| 回答 | 効果 |
|---|---|
| **Yes** | この呼び出しを実行します |
| **Yes, and don't ask again for** `rule` | ルールをフォルダーの `settings.local.json` に保存します（コマンドの場合は先に編集できます） |
| **Yes, and don't ask again for** `X, Y, and Z` **commands in** `folder` | 複数の部分からなるコマンドの場合。各部分のルールを保存します。どれも回答の中に名前が示されます |
| **Yes, allow reading from** `X/` | チャットの残りの間、チャットがそのフォルダーを読めるようにします |
| **Yes, and don't ask again for** `host` | サンドボックス内のコマンドが新しいホストに接続する場合。`web_fetch(domain:host)` を保存します |
| **Yes, and switch to accept edits** | チャットを Accept edits に切り替えます |
| **Yes, allow all edits in** `X/` **during this session** | そのフォルダーをチャットに追加し、Accept edits に切り替えます |
| **No** | 呼び出しは実行されず、ターンが停止します。メモ（Tab）を付けると、そのメモを理由としてターンが続きます |

承認は 30 分間待機し（`approvals.timeoutMinutes`）、その後拒否されます。

## 質問

Aristra Code は選択式の質問をすることがあります。一度に 1 から 4 問で、それぞれに選択肢があります。いつでも自分の言葉で回答でき、**Chat about this** を選んで先に話し合うこともできます。質問は Don't ask 以外のすべてのモードで行われ、スクリプトの実行では行われません。プランモードでは、計画を書く前にこの方法で質問します。

## プランモード

計画を立てる価値のあるタスクでは、Aristra Code が自分からプランモードに入ります。自分で選ぶこともできます。調査して計画を `~/.aristra/plans/<chat>.md` に書き、先に進むかどうかを尋ねます。

- **Yes, and use auto mode**（Auto がオフの場合は bypass permissions か accept edits）：そのモードでプランモードを抜けます。
- **Yes, manually approve edits**：Manual に切り替えてプランモードを抜けます。
- **Tell Aristra what to change**：計画を修正します。

Ctrl+G で計画をエディターで開けます。保存した内容が、承認する計画になります。

## Auto モードのレビュアー

Auto モードでは、本来なら確認を求めるものが、あなたの代わりにレビュアーモデルに回されます。読み取り、検索、Accept edits で許可されるものは、レビュアーを通さずに実行されます。拒否ルール、常にあなたの確認が必要なツール、レビュアーが承認できない安全性のチェック（危険な `rm`、別のワークツリー）がレビュアーに届くことはありません。保護されたファイルへの書き込みはレビュアーが判断します。

- **レビュアーが見るもの**：あなた自身の発言、エージェントのそれまでの呼び出し（結果は除くため、ウェブページがレビュアーに働きかけることはできません）、データとしての `AGENTS.md`、そして操作そのものです。
- **ブロックした場合**は、エージェントにその理由と、回避しないよう伝えます。判断できない場合、呼び出しは拒否され、許可されることはありません。長すぎて全体を読めない操作や、レビュアーのないチャット（`review.enabled: false`）では、代わりにあなたに確認を求めます。
- **3 回連続、またはチャット内で 20 回ブロックすると**、代わりにあなたに確認を求めます。
- **`/retry`** を使うと、直前にブロックされたステップを、そのままの内容で 1 回だけ実行させられます。
- **レビューするもの**：Aristra のモデルと ChatGPT のプランでは、Aristra のレビュアーが無料でレビューします。自分のキー、カスタムエンドポイント、ローカルモデルでは、そのモデル（または `review.model`）がレビューし、そのモデルと同じように支払われます。`autoMode`（`allow`、`soft_deny`、`environment`）と `review.policy` で、レビュアーへの独自の指示を追加できます。

## ウェブからモードを変更する

[Remote Control](/ja/code/remote-control) で共有したチャットでは、ウェブサイトのモードピッカーで、コンピューター上のチャットのモードを切り替えられます。確認なしで実行できる範囲が広がるモードにする場合は、先に新たなサインインの確認が必要です。
