## サブエージェント

Aristra Code は、タスクの一部をサブエージェントに任せることができます。サブエージェントは独自のコンテキストを持ち、バックグラウンドで作業して結果を報告するエージェントです。大規模な検索をメインのチャットから切り離したいときや、複数の調査を同時に進めたいときに使います。頼むこともできますし（「この 3 つのモジュールを並行して調べて」）、Aristra Code に判断を任せることもできます。

| 組み込みの種類 | 用途 |
|---|---|
| `general-purpose` | あらゆるタスク。バックグラウンドエージェントが使えるすべてのツールを使います |
| `Explore` | コードベース全体を対象にした読み取り専用の検索 |
| `Plan` | 読み取り専用の計画。進め方と関係するファイルを設計します |

各サブエージェントは、チャットのフォルダーで、チャットのモードとモデルを使って作業します（呼び出しで別のものを指定した場合を除く）。また、3 階層まで独自のサブエージェントを起動できます。1 つのチャットで同時に実行できるのは、エージェントが起動したエージェントも含めて 20 個までです。承認は、エージェントの名前とともに、連鎖の最上位にあるあなたのチャットで求められます。

**表示される内容**：ステータス行には実行中のエージェントの数が表示され（「2 local agents」）、`/tasks` ではそれぞれが何をしているかの短い説明とともに一覧表示されます。Enter キーで 1 つを開くと、そこで入力したものはそのエージェントに送られます。エージェントが完了すると、チャットにその要約が 1 行で表示され、Aristra Code が結果を読んで作業を続けます。

## チャットをフォークする

```text
/fork write the migration for the new schema
```

フォークは、このチャットのコンテキストをすべて持った状態で始まるサブエージェントなので、説明は不要です。頼んだことを 1 つだけ実行し、その間もここで作業を続けられます。完了すると結果を報告します。自分でチャットのコピーで続けたい場合は、代わりに `/branch` を使います。

## カスタムエージェント

`~/.aristra/agents/`（すべてのフォルダー）、またはプロジェクトの `.aristra/agents/`（信頼したあと）に Markdown ファイルを置くと、エージェントの種類を追加できます。形式は Claude Code と同じです。

```markdown .aristra/agents/migration-reviewer.md
---
name: migration-reviewer
description: Reviews database migrations for locking, data loss and rollback safety
tools: read_file, grep, glob, shell
model: sonnet
---

You review database migrations. For each migration, check ...
```

| フィールド | 意味 |
|---|---|
| `name`、`description` | エージェントの名前と用途（モデルに表示されます）。どちらかがないファイルはスキップされます |
| `tools`、`disallowedTools` | 使えるツール。`mcp__server` でサーバーのツールを指定します |
| `model` | `inherit`、`sonnet`、`opus`、`haiku`、`fable`（この 4 つはチャットが Claude のモデルを使っている場合のみ）、またはモデル ID |
| `effort` | 推論の深さ |
| `permissionMode` | エージェントが実行されるモード。ただし、チャットが `acceptEdits`、`auto`、`bypassPermissions`、`plan` の場合は、チャットのモードが維持されます |
| `maxTurns` | モデルのラウンド数の上限 |
| `isolation` | `worktree` にすると、専用の git ワークツリーが割り当てられます |
| `skills`、`hooks`、`mcpServers`、`memory` | 読み込むスキル、実行中に有効なフック、独自の MCP サーバー、独自のメモリフォルダー |
| `initialPrompt` | チャット全体をこのエージェントとして実行するときに、最初のメッセージの前に置かれます |
| `color` | 一覧での色。red、blue、green、yellow、purple、orange、pink、cyan のいずれか |
| `omitClaudeMd` | `true` にすると、フォルダーの指示ファイルを含めません |

本文がそのエージェントのシステムプロンプトになります。プロジェクトのエージェントは同じ名前の自分のエージェントより優先され、組織のエージェントはその両方より優先されます。

### チャット全体をエージェントとして実行する

`aristra --agent migration-reviewer` を実行すると、エージェントのプロンプト、ツール、モデルで動くチャットが始まります。Aristra Desktop では、Code の新しいチャットの **+** メニューに、エージェントが **Run as …** として一覧表示されます。`agent` の設定で、新しいチャットの既定のエージェントを指定できます。

## ワークツリー

`isolation: worktree` を指定したサブエージェントには、`.aristra/worktrees/agent-<id>` に専用の git ワークツリーが割り当てられるため、並行して動くエージェントが同じファイルを編集することはありません。完了したとき、変更のなかったワークツリーは削除されます。変更のあったワークツリーは残り、そのパスとブランチが報告に含まれます。

## チャット間のメッセージ

Aristra Code は、サブエージェントや、このコンピューターで今開いているか作業中の他の Aristra のチャットに、名前を指定してメッセージを送れます。「API の作業をしているチャットに、スキーマが変わったと伝えて」のように頼みます。メッセージは、別のチャットからのものという印付きでそのチャットに届きます。送信元と権限モードが異なるチャットはメッセージを受け取らず、そのことが送信元に伝えられます。

## ワークフロー

大規模に作業を分散させる場合（「すべてのパッケージをレビューして」「これを複数の観点から調べて」）は、ワークフローを頼みます。Aristra Code は、多数のエージェントを決まった順序（並列、フェーズごと、またはパイプライン）で実行する短いスクリプトを書きます。ルールで許可されている場合（保存済みのワークフローなら `workflow(<name>)`）やモードで確認しない設定の場合を除き、実行の前に説明とフェーズを表示して確認を求めます（Ctrl+E でスクリプトを表示します）。Auto モードではレビュアーが判断します。

- 実行はバックグラウンドで行われ、同時に最大 16 個のエージェントが動きます。コンピューターの CPU コア数から 2 を引いた数のほうが少なければ、その数までです。
- `/workflows` では、各実行のフェーズとエージェントが進行に合わせて表示されます。キー操作でエージェントを停止、一時停止、再試行、スキップでき、**s** でスクリプトを名前付きのワークフローとして保存できます。
- 保存したワークフローは `~/.aristra/workflows/` かプロジェクトの `.aristra/workflows/` に置かれ、`/<name> args` で実行します。
- Aristra Code には `/deep-research <question>` が付属しています。複数の観点からウェブを検索し、懐疑的な立場のエージェントにすべての主張を確認させ、出典付きのレポートを書きます。

設定で `disableWorkflows: true`（または `enableWorkflows: false`）にするか、`ARISTRA_DISABLE_WORKFLOWS=1` を設定すると、ワークフローがオフになります。
