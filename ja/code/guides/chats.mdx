チャットは、Aristra Code との 1 つの会話です。フォルダー、モデル、モード、そして履歴を持ちます。コンピューター上のすべてのサーフェスで、同じチャットが表示されます。

## チャットを探して再開する

| やりたいこと | 方法 |
|---|---|
| このフォルダーで新しいチャットを始める | `aristra`、またはチャットで `/new` |
| このフォルダーの最新のチャット | `aristra -c` |
| ID でチャットを開く | `aristra resume <id>`、または `aristra attach <id>` |
| 選択画面から選ぶ | `aristra resume`、または `/resume` |
| 一覧を表示する | `aristra sessions`（このフォルダー）、`--all`（すべてのフォルダー）、`--json` |

チャットは、[ワークツリー](/ja/code/guides/git)に移さない限り、始めたときのフォルダーを使い続けます。チャットの ID は、チャットを終了したとき、`aristra sessions` を実行したとき、`aristra run --output json` の結果に表示されます。

複数のチャットを同時に実行できます。それぞれのチャットは一度に 1 つのターンを実行します。ターンの実行中に送ったメッセージは、次のステップでそのターンに加わる（Enter）か、ターンの終了を待ちます（`/queue`）。

## ブランチ、フォーク、補足の質問

| コマンド | 動作 |
|---|---|
| `/branch [name]` | このチャットを現時点の状態で新しいチャットにコピーし、コピーで続けます。元のチャットはそのまま残ります |
| `/fork <directive>` | このチャットのコンテキストをすべて持つバックグラウンドエージェントを起動し、指示を実行して報告させます。その間もここで作業を続けられます |
| `/btw <question>` | 実行中のターンを中断せずに、チャットについて簡単な補足の質問をします。回答は入力欄の上に表示され、チャットには追加されません |

## チェックポイント

フォルダーのあるチャットでは、各ターンがチェックポイントから始まります。ターン内で Aristra Code がファイルツールで初めてファイルを変更する前に、そのファイルがバックアップされます。チャットには最新の 100 個のチェックポイントが保持されます。

自分のメッセージの前の状態に戻るには、ターミナルでは `/rewind`（または空の入力欄で Esc キーを 2 回）、Aristra Desktop ではメッセージの **Restore to here** を使います。

- **Restore code** は、それ以降にエージェントがファイルツールで変更したファイルを元に戻します。
- **Restore conversation** は、すべてのサーフェスで、そのメッセージとそれ以降のメッセージをすべて削除し、メッセージを入力欄に戻して編集できるようにします。モデルが見る内容はその時点のものになり、チャットのモードもその時点のものに戻ります。そのメッセージのあとで要約されたチャットは、そこに戻れません。
- **Restore code and conversation** は両方を行います。

コードの選択肢は、そのメッセージのあとにエージェントがファイルを変更した場合にだけ表示されます。

<Note>
チェックポイントが追跡するのは、Aristra Code のファイルツールによる変更です。Aristra Code が実行したコマンド（`npm run format`、マイグレーションなど）や自分自身による変更は元に戻りません。それらには git を使ってください。
</Note>

## タイトル

チャットのタイトルは、最初のターンの実行中にモデルが書くか、`/rename <title>` で設定します。設定の `auxiliary.title` で、タイトルを書くモデルを選べます。`"off"` にすると、メッセージの冒頭の語句がタイトルになります。

## エクスポートと削除

```sh
aristra sessions export <id>                 # Markdown, in ~/.aristra/exports/
aristra sessions export <id> --format json
aristra sessions delete <id>                 # asks first; --yes to skip
```

チャットでは、`/export` と `/export json` でチャットを保存し、`/copy` で最新の返信をコピーします（`/copy 2` ではその 1 つ前）。返信にコードブロックがある場合は、`copyFullResponse` がオンでない限り、どれをコピーするかを尋ねます。チャットを削除すると、その履歴とファイルが削除されます。

## チャットの保存場所

コンピューター上のチャットは `~/.aristra/runtime.sqlite` に保存され、チャットに属するファイル（添付ファイル、長いコマンドの出力、チェックポイント）は `~/.aristra/attachments/<chat>/` に保存されます。どちらも自分だけが読めます。[Remote Control](/ja/code/remote-control) で共有するか、[クラウドチャット](/ja/code/cloud-chats)でない限り、チャットの履歴が他の場所に保存されることはありません。ただし、各ターンでは会話がチャットのモデルのプロバイダーに送られます（チャットが Aristra のモデルを使う場合は Aristra を経由します）。[セキュリティ](/ja/code/security)を参照してください。

## ターンに回答が必要なのに誰もいない場合

承認は 30 分間待機します（`approvals.timeoutMinutes`）。スマートフォンに共有したチャットや、スケジュールタスクが始めたチャットでは 2 時間待機します。待機時間が終わるとステップは拒否され、モデルには誰も回答しなかったことが伝えられ、ターンはそのステップなしで続きます。誰も接続していない場合、Aristra はコンピューターに通知を表示します。

[非対話モード](/ja/code/non-interactive)では、回答できる人がまったくいないため、確認が必要なものはすぐに拒否されます。

## 返信が途中で切れた場合

モデルの返信が出力の上限に達すると、Aristra Code は止まったところから続けるようモデルに最大 3 回依頼し、それでも終わらなければ通知とともにターンを終了します。

## Aristra がターンの途中で止まった場合

Aristra Code は作業しながら保存していきます。ターンの途中でランタイムが停止したりコンピューターが再起動したりした場合、そのターンは通知とともに中断済みとして記録されます。完了していない各ステップにも印が付けられ、モデルはそれを繰り返す前に確認します。続けるにはメッセージを送ってください。

## 他のエージェントのチャット

Aristra Desktop では Claude Code と Codex のセッションを取り込めます。また、`aristra import claude-code`（または `codex`）で設定を取り込めます。取り込んだ各セッションは、そのフォルダーで Aristra Code が続けるチャットになります。
