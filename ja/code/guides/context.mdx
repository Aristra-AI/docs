モデルのコンテキストとは、モデルが 1 つのターンで読むものすべてです。Aristra Code の指示、自分の指示ファイル、使えるツール、それまでの会話、そしてメッセージです。サイズに上限があるため、長いチャットは大きくなるにつれて要約されます。

## モデルが見る内容

各ターンでモデルが受け取るのは次のものです。

1. **システムプロンプト**：チャットごとに一度作成されて保持されるため、プロバイダーのプロンプトキャッシュがターンをまたいで有効なままになります。固定部分が先頭にあり、同じモデルのすべてのチャットで同一なので、そのモデルの新しいチャットやモードの変更でも、その部分はキャッシュから読み込まれます。Aristra Code の動作、コンピューターとフォルダー、モードで許可されていること、[指示ファイル](/ja/code/guides/memory)、そして git リポジトリではそのスナップショット（ブランチ、メインブランチ、`git status`、直近 5 件のコミット）が含まれます。
2. **会話**：チャットが長い場合は、古い部分が要約されています。
3. **このターンのコンテキスト**：前のターンから変わった場合にだけ含まれます。プロフィール、このフォルダーに関するアカウントのメモリ、起動できるエージェント、リポジトリのメモ、スキル、MCP サーバーの指示、終了したバックグラウンドのコマンドの結果です。
4. **メッセージ**と添付したファイル。

## コンテキストを占めるものを確認する

```text
/context
```

を実行すると、モデルのコンテキストを占めるものがグリッドで表示されます。システムプロンプト、ツール（MCP のツールは別）、MCP サーバーの指示、指示ファイル、スキル、メッセージ、要約のために確保された領域、空き領域です。その下に、各 MCP ツールと指示ファイルのサイズと、大きなコマンド出力やほぼいっぱいのウィンドウなどについての提案が表示されます。フルスクリーンレンダラーでは一覧が短縮されます。`/context all` で全体を表示できます。Aristra Desktop では、チャットの `/` メニューで **Context usage** を選択します。

ステータス行には、コンテキストの使用状況が表示されます。60% で黄色、80% で赤になります。

## 要約（圧縮）

チャットがモデルの上限に近づくと、まず古いコマンドやツールの出力がファイルに保存され、コンテキストから消去されます。それでも足りない場合は、Aristra Code が古いメッセージを要約し、モデルは要約から続けます。直近のやり取りは一字一句そのまま残り（`/compact` ではすべてを要約します）、直近に扱ったファイルのうち最大 5 つが読み直されます。その時点が近づくと、ステータス行でカウントダウンが表示されます。

- `/compact` ですぐに要約します。要約に残す内容を指示として追加できます：`/compact keep the API decisions`。
- `/autocompact <tokens>` で、チャットのモデルについて、要約を始めるまでにコンテキストをどこまで使うかを設定します。100k から 1M（`500k`、`200000`）、またはモデル自体のウィンドウを使う `auto` を指定します。`/autocompact` だけを実行すると、現在の設定が表示されます。設定はモデルごとに設定ファイルに保存され（`modelSettings.<model>.autoCompactWindow`）、`ARISTRA_AUTO_COMPACT_WINDOW` で上書きできます。

すべてのサーフェスには、引き続き会話全体が表示されます。要約を使うのはモデルだけです。指示ファイルは要約のあとに読み直されます。

<Tip>
新しいタスクには新しいチャットを始めるのが、コンテキストを小さく保ついちばん安上がりな方法です。大きなチャットが 1 時間以上アイドル状態になると、ステータス行でそれが提案されます。
</Tip>

## 要約を書くモデル

要約モデルを設定していれば（`auxiliary.summary`）そのモデルが、設定していなければチャット自体のモデルが要約を書きます。チャット自体のモデルはチャットの中で要約を書くため、チャットのプロンプトキャッシュを再利用できます。[モデル](/ja/code/configure/models)を参照してください。
