## バックグラウンドのコマンド

時間のかかるコマンドがチャットを止めることはありません。

- **タイムアウトに達すると**（既定は 2 分、モデルが求めれば最大 10 分）、まだ実行中のコマンドは停止されずにバックグラウンドに移り、Aristra Code はそれまでの出力を受け取ります。
- コマンドの実行中に **Ctrl+B**（tmux の中では 2 回）を押すと、自分でコマンドをバックグラウンドに移せます。
- **開発サーバーやファイル監視**は、Aristra Code が求めればバックグラウンドで起動します。

バックグラウンドのコマンドは、ターンをまたいで実行を続けます。コマンドが終了するとチャットに知らされ、Aristra Code がその出力を読みます。チャットやランタイムが停止するとコマンドも停止し、コマンドを停止するとそれが起動したものもすべて終了します。

Aristra Code は、サーバーを独自のバックグラウンドコマンドとして実行します。末尾が `&` のコマンドはバックグラウンドコマンドになります。`&`、`nohup`、`disown`、`setsid` で自身の一部をバックグラウンドに回すコマンドは、分割するよう差し戻されます。残して動かしたものも、そのコマンドとともに終了してしまうためです。

```text
/tasks
```

を実行すると、バックグラウンドで動いているものすべて（コマンド、モニター、[エージェント](/ja/code/guides/subagents)、ワークフロー）が一覧表示されます。Enter キーでエージェント（そこで入力したものはエージェントに送られます）やワークフローを開き、x キーでいずれかを停止します。ステータス行には、その数が表示されます（「1 shell」「2 local agents」）。Aristra Desktop では、メッセージ欄の上に一覧表示され、それぞれに出力と停止ボタンがあります。

## モニター

モニターは、出力の行がイベントとしてチャットに届くバックグラウンドコマンドです。エラーに一致するログの行、デプロイの状態の変化、テストの実行の完了などです。何かを監視するよう頼むと（「ビルドが失敗したら教えて」）、Aristra Code がモニターを起動します。各モニターは既定で 5 分間、最大 30 分間実行され、そのあと通知とともに停止します。より長く監視する場合は、Aristra Code がもう一度起動できます。モニターは `/tasks` に表示されます。

## プロンプトを繰り返す：/loop

```text
/loop 5m check the deploy and tell me when it's done
/loop 30m /code-review
/loop check CI until it passes        # no interval: Aristra Code picks when to look again
```

`/loop` は、プロンプトかコマンドを一定の間隔で実行します。間隔を指定しない場合は、Aristra Code が自分でペースを決め、確認すべきことがあるときに再開します。

普段の言葉でスケジュールを頼むこともできます（「10 分ごとにデプロイを確認して」「2 時 30 分にデプロイの確認をリマインドして」）。Aristra Code は、このチャットでプロンプトをスケジュールします。

- スケジュールしたプロンプトは、チャットがアイドル状態のときにだけ実行され、返信の途中で実行されることはありません。
- 1 つのチャットに最大 50 個まで設定できます。繰り返しのものは 7 日後に停止します。
- これらは実行中の Aristra Code の中にあり、ランタイムが停止すると停止します。チャットのあとも続けるべき作業の場合、Aristra Code は代わりにスケジュールタスクを保存します。その際は先に確認を求めます。

## スケジュールタスク

スケジュールタスクは、決まった時刻（1 回のみ、毎時、毎日、平日、毎週。コンピューターの時刻に基づく）にフォルダーでプロンプトを実行します。たとえば、開いているプルリクエストの朝のまとめや、週次の依存関係のチェックなどです。タスクはコンピューターに保存されてそこで実行され、料金はかかりません。各実行はそれぞれ独立したチャットになり（頼んだ場合は、タスクを作成したチャットへの新しいメッセージになります）、Code タブの **Inbox** に未読のドット付きで一覧表示されます。承認は 2 時間待機します。

作成方法は 3 つあります。

- **チャットで頼む**：「平日の毎朝 9 時にビルドを確認して、失敗したものを教えて」。保存する前に、Aristra Code がタスクのスケジュール、プロンプト、フォルダー、モデル、権限モードを表示します。タスクはチャットのあとも実行され続けるため、どの権限モードでも確認を求めます。タスクはチャットのフォルダー、モデル、モードを引き継ぎ、Aristra Code が別のものを選ぶことはできません。
- **Aristra Desktop で**：Chats & tasks で **New** › **Scheduled task** を選ぶか、⌘K › **New scheduled task** を選びます。
- **ターミナルで**：

```sh
aristra tasks add "Check the build and report what fails" --every weekday --at 09:00
aristra tasks add "Summarize last week's commits" --every monday --at 08:30 --name "Weekly notes"
aristra tasks add "Remind me to send the report" --once "2026-03-01 08:00"
aristra tasks                      # list them, with each one's next run and last run
aristra tasks pause <id>           # also: resume, run (once, now), remove
```

ターミナルアプリでは、`/schedule` で一覧を表示し、`/schedule pause|resume|run|remove <number>` で変更します。

実行でできること、できないこと：

- 各実行は、タスクを作成したチャットを見ていない新しいチャットなので、プロンプトはそれだけで完結している必要があります。ただし、実行結果をそのチャットに戻すよう頼んだ場合（または Aristra Desktop の **Each run** でチャットを選んだ場合）は、各実行はそのチャットへの新しいメッセージになります。
- 実行中に質問することや、タスクをスケジュールすることはできません。
- 新しく報告することがない実行は、静かにその旨を記録します。実行はタスクの一覧に既読の状態で保存され、通知は届きません。失敗した実行は、必ず理由とともに通知されます（たとえば残高がない場合）。3 回続けて失敗すると、タスクは一時停止します。原因を解決したら再開してください。
- [プラン](/ja/account/plans)があれば、タスクは各実行の結果を Aristra アカウント経由で Telegram やメールにも送れます。ターミナルでは `--send telegram,email` を付け、Aristra Desktop では **Also send each result to** を選び、チャットでは頼みます（「結果をメールで送って」）。失敗した実行も送られます。新しく報告することがない実行は何も送りません。Telegram を使うには、アカウントで Telegram を連携しておく必要があります。結果を送れなかったときは、タスクの一覧に理由が表示されます。
- コンピューターがスリープ中や電源オフの間に実行できなかった分は、戻ったときに 1 回の実行で埋め合わせるか、タスクでそう選んでいればスキップします。

バックグラウンドサービスがオンなら、スケジュールタスクはすべてのウィンドウを閉じていても予定どおりに実行されます。オフの場合は、次に Aristra Code が動いたときに実行されます。2 分以上遅れた実行は実行できなかったものとみなされ、1 回の実行で埋め合わせるか、そう選んでいればスキップします。タスクは、このコンピューターが Aristra にサインインしている間に実行されます。初めてタスクを作成したときにサービスがオフだと、Aristra がそのことを一度だけ知らせます。

[プラン](/ja/account/plans)があれば、コンピューターの電源が切れていても、タスクを Aristra のクラウドで実行できます。[スケジュールタスク](/ja/scheduled-tasks)を参照してください。

## バックグラウンドサービス

```sh
aristra service install     # keep Aristra Code running, now and at every login
aristra service status
aristra service uninstall
```

macOS では launchd エージェント、Linux では systemd のユーザーユニットとして動きます。更新にも追従します。Aristra Desktop では、Settings › General › **Keep Aristra running in the background** で同じサービスがインストールされます。誰もログインしていない Linux サーバーでは、`loginctl enable-linger $USER` を実行してください。

サービスがない場合、ランタイムはサーフェスが必要としたときに起動し、何も接続されておらず何も実行されていない状態が 10 分続くと停止します（`runtime.idleExitMinutes`）。ターン、バックグラウンドのコマンド、待機中の承認がある間は動き続けます。

## 通知

| 接続しているサーフェス | 通知するもの |
|---|---|
| ターミナル | ターミナル。iTerm2、kitty、Ghostty で通知し、Apple のターミナルではベルを鳴らします。`ARISTRA_NO_NOTIFY=1` でオフにできます |
| Aristra Desktop | アプリ |
| なし | Aristra Code がシステム通知で知らせます。`runtime.notifications: false` でオフにできます |

承認が待機しているとき、スケジュールした実行が終わったとき、スマートフォンやウェブから変更が届いたときに通知されます。また、Aristra Code が自分から通知を送ることもあります。たとえば、離れている間に時間のかかるタスクが終わったときです。コンピューターの前で Aristra を使っている間は通知を送りません。
