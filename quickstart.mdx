---

This guide takes you from nothing installed to a first finished change. It uses the terminal; the same chat works in [Aristra Desktop](/surfaces/desktop) too.

<Steps>
  <Step title="Install">
    ```sh
    curl -fsSL https://aristralabs.com/install.sh | sh
    ```

    This installs the newest release for your machine (macOS on Apple silicon or Intel, Linux on x64 or arm64) into your home folder, with no root access. If `~/.local/bin` is not on your `PATH` yet, the installer adds it to your shell profile and says so. Open a new terminal afterwards.

    Check the install:

    ```sh
    aristra --version
    aristra doctor
    ```

    `aristra doctor` checks your setup and marks each line `ok` or `fix`, with how to fix it. On Windows, use WSL2; see [Setup](/setup).
  </Step>

  <Step title="Start it in a project">
    ```sh
    cd ~/code/my-project
    aristra
    ```

    The first run asks only what it still needs, one screen at a time:

    1. **Sign in to Aristra.** Every chat needs an Aristra account, including chats on your own keys or on a local model. The account is free: see [what is free and what a plan adds](/account/overview). With a browser, sign-in opens a page on aristralabs.com; over SSH it shows a code to enter on any device. Esc skips it, and `/login` signs in later.
    2. **Choose the model new chats start with.** Each choice says who pays: your Aristra balance, your ChatGPT plan, your own key, or "runs on this computer". Change it any time with `/model`.
    3. **Trust the folder.** Aristra Code reads, edits and runs files in a folder you trust. "No, exit" is selected first; press Down, then Enter, to trust it. The answer is saved for the repository and its subfolders.
  </Step>

  <Step title="Ask for a change">
    Type what you want done and press Enter:

    ```text
    › Find why the date parser fails on leap years and fix it. Run the tests when you are done.
    ```

    You will see:
    - The reply stream in as Markdown.
    - Each step as one line: `Read src/date.ts`, `Search "leap"`, `Edit src/date.ts`, `npm test`.
    - Each edit's diff, and each command's output, cut to a few lines. Ctrl+O opens the newest step's full output.
    - The status line with what it is doing and how full the model's context is, and the footer with the mode, the branch's pull request, the model and who pays.
  </Step>

  <Step title="Approve what it asks">
    New chats start in **Manual** mode: reading, searching and commands that only read run on their own (with the sandbox on, so do commands in it), and other changes ask first. An approval shows the exact command or diff with three answers:

    - **Yes** for this one step.
    - **Yes, and don't ask again** for this kind of step, which saves a rule (or allows edits for the rest of the chat).
    - **No**, with a note the model reads if you press Tab first.

    Press Shift+Tab to cycle modes: **Accept edits** (edits in the folder run on their own), **Plan** (explore and propose first), **Auto** (Aristra's reviewer decides what would ask) and back to Manual. See [Permissions](/configure/permissions).
  </Step>
</Steps>

## Everyday use

| You want to | Do this |
|---|---|
| Start in this folder | `aristra` |
| Start with a prompt | `aristra "explain the build system"` |
| Continue this folder's newest chat | `aristra -c` |
| Go back to an earlier chat | `aristra resume`, or `/resume` in a chat |
| Open a chat running elsewhere | `aristra attach <id>` |
| Run one turn in a script or CI | `aristra run "fix the lint errors" -o json` |
| See this folder's chats | `aristra sessions` (`--all` for every folder) |
| Choose another model | `/model`, or `aristra models` to list them |
| Add a provider key | `aristra keys add openai` (or `anthropic`, `gemini`, `openrouter`) |
| Change a setting | `aristra config set permissions.defaultMode acceptEdits` |
| Bring your Claude Code or Codex setup | `aristra import claude-code` (or `codex`), with a preview first |
| Check your setup | `aristra doctor` |

In a chat, `/help` lists every command and key.
