## Configuration requise

| Système | Pris en charge |
|---|---|
| macOS | Apple silicon et Intel. La version Apple silicon s'installe aussi dans un shell qui tourne sous Rosetta |
| Linux | x64 et arm64 avec glibc. Le bac à sable, quand vous l'activez, nécessite bubblewrap (`bwrap`). Alpine (musl) n'est pas encore pris en charge |
| Windows | Via WSL2 avec une distribution Linux comme Ubuntu, en utilisant la version Linux. Les pages de connexion s'ouvrent via le programme que désigne `$BROWSER` (sous WSL, généralement `wslview`). À défaut, connectez-vous avec un code |

Chaque version embarque tout ce dont elle a besoin, y compris ses propres Node et Python : rien d'autre n'est à installer au préalable, à part `curl` ou `wget`.

## Installer

```sh
curl -fsSL https://aristralabs.com/install.sh | sh              # the latest release
curl -fsSL https://aristralabs.com/install.sh | sh -s stable    # the stable channel
curl -fsSL https://aristralabs.com/install.sh | sh -s 1.2.1     # one version
```

Le script :

1. Choisit la version adaptée à votre machine.
2. La télécharge et vérifie sa somme de contrôle SHA-256 par rapport au manifeste de la version.
3. L'installe dans `~/.local/share/aristra/versions/<version>/` et fait pointer `~/.local/bin/aristra` vers elle.
4. Ajoute `~/.local/bin` au profil de votre shell quand ce dossier n'est pas dans votre `PATH`, ou quand un autre `aristra` passe en premier (pour fish, il affiche la commande `fish_add_path` à lancer).
5. Propose de supprimer un ancien `aristra` installé avec npm ou bun qui passerait en premier dans votre `PATH`.
6. Propose de lancer `aristra`.

Les questions sont posées dans le terminal : elles fonctionnent donc avec `curl | sh`. Sans terminal, ou avec `ARISTRA_NON_INTERACTIVE=1`, il ne demande rien et prend la réponse sûre.

<Warning>
L'installateur refuse de s'exécuter sous `sudo` depuis votre propre shell, car il installerait dans le dossier personnel de root. Pour installer volontairement pour root via sudo, définissez `ARISTRA_INSTALL_ALLOW_SUDO=1`. Dans un conteneur ou une CI qui tourne en root, il installe pour root comme d'habitude.
</Warning>

## Canaux de publication

| Canal | Ce que c'est |
|---|---|
| `latest` | La version la plus récente. Par défaut |
| `stable` | Une version publiée depuis environ une semaine sans problème |

Le canal depuis lequel vous installez est mémorisé, et `aristra update` le suit. Les nouvelles versions sortent environ chaque semaine.

## Mettre à jour, changer de version et revenir en arrière

```sh
aristra update            # the newest release on your channel
aristra update --check    # only say whether there is one
aristra install latest    # switch to the latest channel
aristra install stable    # switch to the stable channel
aristra install 1.2.1     # switch to exactly that version (a rollback when it is older)
```

La version utilisée et les deux plus récentes restent sur le disque : revenir à l'une d'elles ne télécharge donc rien. Une mise à jour n'interrompt jamais un chat en cours : le runtime déjà lancé s'arrête une fois inactif, et la commande suivante démarre le nouveau.

[Aristra Desktop](/fr/code/desktop) embarque sa propre copie d'Aristra Code. Le terminal et l'app de bureau partagent toujours un seul runtime, le plus récent compatible installé.

## Ce qui est installé

```text
~/.local/bin/aristra                 a link to the version in use
~/.local/share/aristra/
  channel                            latest or stable
  versions/<version>/                the program, its runtime and their licenses
```

Vos données ne sont pas ici : les chats, les paramètres, les journaux et les secrets se trouvent dans `~/.aristra`. Consultez [Fichiers et variables d'environnement](/fr/code/reference/environment).

## Désinstaller

Il n'existe pas encore de commande de désinstallation. Pour supprimer Aristra Code et tout ce qu'il conserve :

```sh
aristra logout                    # sign out and remove this computer from your account
aristra service uninstall         # if you turned on the background service
aristra runtime stop --now        # stop the runtime
rm ~/.local/bin/aristra
rm -rf ~/.local/share/aristra      # every installed version
rm -rf ~/.aristra                 # your data: chats, settings, logs, secrets
```

Sur un Mac, supprimez aussi du trousseau de session la clé qui a scellé vos secrets :

```sh
security delete-generic-password -s Aristra-credentials
```

Sous Linux avec un trousseau de clés, lancez `secret-tool clear service Aristra-credentials`. Supprimez ensuite le bloc que l'installateur a ajouté au profil de votre shell, s'il y en a un.

<Note>
Aristra Desktop utilise le même dossier `~/.aristra`. Le supprimer supprime aussi les chats de l'app de bureau sur ce Mac.
</Note>
