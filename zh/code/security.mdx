## 哪些内容会离开你的电脑

你电脑上的对话保存在`~/.aristra`中。会发送出去的内容，以及发送给谁：

| 内容 | 发往哪里 | 何时 |
|---|---|---|
| 模型调用：对话内容和提供的工具 | 对话的来源：Aristra、OpenAI（你的ChatGPT套餐）、你密钥对应的服务商、你的自定义端点。对于你电脑上的模型则不发送 | 每次模型调用 |
| 你的个人资料：你的名字、职业和**About you**备注 | 从Aristra读取 | 对话的各轮中，最多每十分钟一次 |
| 你的账户中与这个文件夹相关的记忆 | 从Aristra读取，带有仓库远程地址和文件夹名称的标记，绝不包含其路径 | 开启了记忆的对话的各轮中 |
| Aristra Code保存到记忆中的内容，以及关于仓库的笔记 | Aristra | 保存时 |
| 网页搜索 | Aristra的搜索，或使用你自己的密钥时为Brave | 搜索时 |
| Aristra的搜索无法提供服务时的搜索词 | Exa、Parallel、Firecrawl或Keenable的免费公共搜索 | 除非`web.keylessFallback`为`false` |
| 连接器调用 | Aristra，由它执行调用 | 当对话使用连接到你账户的应用时 |
| 对你添加的MCP服务器的调用 | 该服务器 | 当对话使用它时 |
| 在云端沙箱中运行命令时，你文件夹中的文件 | Aristra的沙箱或E2B | 只有在你选择使用时 |
| 网页 | 直接从你的电脑获取 | 读取网页时 |
| Auto模式的审核模型检查的步骤 | Aristra的审核模型，或你自己的模型 | 在Auto模式下，针对原本需要询问的操作 |
| 不含内容的使用事件和错误报告 | Aristra | 除非你关闭它们 |
| 共享的对话，或云端对话对这里某个文件夹的调用 | Aristra | 只有在你共享对话或连接文件夹时 |
| Aristra Code发送给你的文件 | Aristra | 当它把文件发送到你的手机或网页版时 |
| 拉取请求状态、`/pr`和Auto-fix | GitHub或GitLab，使用你自己的`gh`或`glab`登录 | 在有拉取请求的分支上 |
| 插件目录和插件 | 你添加的插件市场（默认是来自GitHub的Anthropic插件市场） | 当你添加或更新插件市场，或安装插件时 |

对Aristra模型的调用会经过Aristra的服务器发送到模型服务商，并在你的账户上计量；这些调用不会保存任何关于对话的内容。

### 有套餐和没有套餐时

登录后，无论是否有套餐，Aristra记住的关于你的内容都保存在你的Aristra账户中，所以它会跟随你到网页版、手机和你的其他电脑上。

| | 有套餐 | 没有套餐 |
|---|---|---|
| 对话记录 | 在这台电脑上。从不上传 | 相同 |
| 你共享到网页版的对话 | 它的各轮会作为对话保存到你的账户中，可以被**Search and reference past chats**找到 | 不可用 |
| Aristra记住的关于你的内容 | 你账户的记忆：每一轮都会读取，并由记忆工具写入，所以它会离开这台电脑 | 相同 |
| 关于仓库的笔记 | 这台电脑上的文件，单向复制到你的账户 | 相同 |
| 文件 | 在这台电脑上，除非你把副本保存到你的账户 | 相同 |

未登录时，Aristra不会保留关于你的任何记忆。在每个账户都有记忆功能之前就用文件保存记忆的电脑，会在它第一次以登录状态开始对话时，把这些笔记发送到你的账户一次。

## 登录

`aristra login`（或首次运行）会把这台电脑添加为你Aristra账户的一台设备，可以在浏览器中完成，也可以使用验证码在任意设备上输入（通过SSH，或使用`--device-code`）。它会创建：

- **一台设备**：位于你的账户上，网站的设备列表会显示它，并可以撤销它。
- **一个设备密钥**：在Mac上，它在Secure Enclave中生成，因此无法从芯片中复制出来；在Linux上，它是凭据存储中的一个软件密钥。每次续期登录都会用它签名，所以被盗的令牌在其他地方毫无用处。没有Secure Enclave的Mac（没有T2芯片的Intel Mac、虚拟机）在登录时不使用设备密钥。
- **令牌**：一个有效期15分钟的访问令牌，以及一个有效期30天的刷新令牌，保存在凭据存储中。

`aristra logout`会在这里退出登录并撤销该设备。从网站上让该设备退出登录也会撤销它。

## 机密信息保存在哪里

服务商密钥、MCP机密信息以及每一个登录凭据都保存在Aristra的凭据存储中，绝不会保存在设置文件中。**各使用端可以写入机密信息，但永远无法读回**。存储用你钥匙串中的一个密钥加密；你批准的命令会以你自己的访问权限运行，所以它有可能访问到。在你的权限中添加`"deny": ["read(~/.aristra/**)"]`，可以把智能体的工具和沙箱中的命令挡在外面。

| 存储 | 位置 |
|---|---|
| macOS钥匙串 | `~/.aristra/credentials.enc`，用保存在你登录钥匙串中的随机密钥加密 |
| Linux密钥环 | 同样的加密文件，密钥保存在Secret Service中 |
| 文件 | `~/.aristra/credentials.json`（只有你可以读取），用于没有钥匙串响应的情况（在Linux上，未安装`secret-tool`时也是如此）。`ARISTRA_CREDENTIALS_STORE`会覆盖`credentials.store` |

`credentials.store`（`auto`、`keychain`、`file`）用于选择存储方式；`aristra doctor`会显示当前使用的是哪一种。

## Aristra Code如何受到约束

| 威胁 | 由什么阻止 |
|---|---|
| 网页、文件或工具输出指使智能体做有害的事 | 权限检查和沙箱。外部内容在到达模型时会被标记为不可信。Auto模式的审核模型永远看不到工具结果 |
| 命令试图访问网络或在文件夹之外写入 | 对每条不只是读取的命令进行审批；开启[沙箱](/zh/code/configure/sandbox)后：网络只能通过它的代理访问你允许的主机，只能在对话的文件夹中写入 |
| 恶意的MCP服务器 | 先对照已知恶意软件检查它的软件包，在你信任它之前它的工具都会询问，`"sandbox": true`会让它在沙箱中运行 |
| 仓库的设置试图允许一切 | 文件夹的规则、模式和沙箱设置只有在你信任它之后才会生效，它的`.mcp.json`服务器在启动前会询问。审核模型、机密信息的保存位置和辅助模型只来自你自己的设置 |
| 智能体编辑仓库的设置或智能体文件 | 对`.aristra`、`.claude`、`.git`、`.vscode`、`.idea`、shell启动文件和`.mcp.json`的修改绝不会仅凭一条规则就运行：它们在每种模式下都会询问，在Auto模式下由审核模型决定 |
| 机密信息泄露到日志中 | 看起来像机密信息的值会在工具结果、事件、日志和导出中被遮盖 |
| 笔记本电脑被盗 | 机密信息用你登录钥匙串中的密钥加密，登录与设备密钥绑定。请在网站上撤销该设备 |

<Tip>
在沙箱中，读取默认是开放的。请用拒绝规则关闭凭据文件夹：`"deny": ["read(~/.ssh/**)", "read(~/.aws/**)"]`。
</Tip>

只有你的用户可以与运行时通信：它在一个会对照你的用户账户进行检查的私有套接字上监听，从不在网络上监听。

## 日志

运行时把日志写入`~/.aristra/logs/runtime.log`，其中的机密信息会被遮盖，日志保留七天。`aristra logs`读取日志，`aristra logs -f`实时跟踪日志，`ARISTRA_LOG_LEVEL`设置日志的详细程度。

`aristra diagnostics export`会把一个支持包写入`~/.aristra/diagnostics/`：包括版本、检查结果、你自己的设置文件、表的大小（不含消息）和日志，会再次遮盖机密信息并删除邮箱地址。它不会发送任何内容；在分享之前请先查看其中的内容。

## 遥测

Aristra Code会发送不含内容的使用事件和错误报告。绝不会发送任何提示词、回复、代码、命令、文件内容、文件或文件夹名称、路径、URL、MCP服务器名称或错误信息：每个值都是一个类别、计数、时长、时间，或来自固定列表的标识符（例如模型名称）。未登录时不会发送任何内容，无法发送的事件会被丢弃，绝不会写入磁盘。

| 关闭方式 | 使用事件 | 错误报告 |
|---|---|---|
| 设置 | `telemetry.usage: false` | `telemetry.errors: false` |
| 环境变量 | `ARISTRA_DISABLE_TELEMETRY=1` | `ARISTRA_DISABLE_ERROR_REPORTING=1` |
| 两者都关闭 | `ARISTRA_DISABLE_NONESSENTIAL_TRAFFIC=1` | |
| Aristra Desktop | Settings › General › Privacy › **Share usage data** | **Send error reports** |

环境变量会在运行时启动时读取：设置后请运行`aristra runtime stop`。`aristra doctor`会显示每一项是否开启。
