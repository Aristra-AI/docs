---
title: "目标"
description: "用/goal设置一个条件，Aristra Code会一直工作直到条件成立：测试通过、构建成功、页面能够渲染。"
---

目标是Aristra Code在停止之前检查的一个条件。当一轮即将结束时，一个小模型会阅读对话，判断目标是否已经达成。如果没有达成，这一轮会带着原因继续。如果达成了，目标会被清除，对话中会显示它已经达成，以及花了多长时间、多少轮和多少token。

```text
/goal all tests in packages/api pass and the linter is clean
/goal                # show the current goal
/goal clear          # remove it
```

目标最多4,000个字符。`/goal`只在受信任的文件夹中可用，并且在设置了`disableAllHooks`时不可用。

在Aristra Desktop中，在对话的`/`菜单中选择**Goal**。

## 写出好的目标

目标最好是Aristra Code可以通过运行某些东西来检查的内容，而不是见仁见智的判断：

| 好的目标 | 难以检查的目标 |
|---|---|
| `npm test`通过，且没有跳过的测试 | 代码很整洁 |
| 构建成功，且打包体积小于200 KB | 应用很快 |
| 本地服务器上的`/health`返回200 | API能用 |

把用于检查的命令告诉Aristra Code，写在目标中或你的`AGENTS.md`中，这样每一轮都可以验证，而不是猜测。

## 如何结束

- **已达成**：目标被清除，对话中会说明这一点。
- **未达成**：这一轮会带着检查给出的原因继续。
- **不可能达成**：如果检查判断目标无法达成，目标会被清除，这一轮结束，并说明原因。
- **连续8次未达成**，且中间没有任何工具调用：这一轮仍会结束，目标保留。
- **检查失败**（30秒内没有答复，或者没有为它设置模型）：这一轮结束，目标保留。

当对话中仍有后台工作在运行时，检查会等待它。Esc照常停止这一轮；目标会一直保留，直到你清除它、它被达成，或者检查发现它不可能达成。
