模型的上下文是它在一轮中读取的全部内容：Aristra Code的指令、你的指令文件、它可以使用的工具、到目前为止的对话以及你的消息。上下文有大小限制，所以长对话会随着增长而被总结。

## 模型看到什么

每一轮，模型都会得到：

1. **系统提示词**：每个对话构建一次并保留下来，这样服务商的提示词缓存在各轮之间都能保持有效。它的固定部分放在最前面，在同一模型的每个对话中都相同，所以在该模型上新建对话或切换模式时，这部分也会从缓存中读取。它包含Aristra Code的工作方式、你的电脑和文件夹、当前模式允许什么、你的[指令文件](/zh/code/guides/memory)，在git仓库中还有仓库的快照：当前分支、主分支、`git status`以及最近五次提交。
2. **对话**：对话较长时，较早的部分会被总结。
3. **这一轮的上下文**：只有在与上一轮相比发生变化时才会包含：你的个人资料、你的账户中与这个文件夹相关的记忆、它可以启动的智能体、关于仓库的笔记、你的技能、你的MCP服务器的说明，以及已结束的后台命令的结果。
4. **你的消息**以及你附加的文件。

## 查看占用情况

```text
/context
```

这条命令会以网格形式显示占用模型上下文的内容：系统提示词、工具（MCP工具除外）、你的MCP服务器的说明、你的指令文件、你的技能、消息、为总结预留的空间，以及剩余空间。下方列出每个MCP工具和指令文件及其大小，以及一些建议，例如较大的命令输出或即将占满的窗口。在全屏渲染器中，列表会被缩短；`/context all`会完整显示。在Aristra Desktop中，在对话的`/`菜单中选择**Context usage**。

状态行会显示上下文已用多少：60%时为黄色，80%时为红色。

## 总结（压缩）

当对话接近模型的上限时，较早的命令和工具输出会先被保存到文件中，并从上下文中清除。如果这还不够，Aristra Code会总结较早的消息，模型从摘要继续。最近的一次交流会逐字保留（`/compact`会总结所有内容），它最近处理过的文件中最多有五个会被重新读取。临近这个时刻时，状态行会倒计时。

- `/compact`会立即总结。加上说明可以指定摘要应保留什么：`/compact keep the API decisions`。
- `/autocompact <tokens>`为对话的模型设置上下文用到多满时开始总结：100k到1M（`500k`、`200000`），或者`auto`表示使用模型自己的窗口。单独输入`/autocompact`会显示当前设置。它按模型保存在你的设置中（`modelSettings.<model>.autoCompactWindow`）；`ARISTRA_AUTO_COMPACT_WINDOW`会覆盖它。

每个使用端仍会显示完整的对话；只有模型基于摘要工作。总结之后，你的指令文件会被重新读取。

<Tip>
为新任务开始一个新对话，是让上下文保持精简的最省钱的方法。当一个很大的对话闲置超过一小时时，状态行会给出这个建议。
</Tip>

## 谁来撰写摘要

如果你设置了摘要模型（`auxiliary.summary`），就由它撰写；否则由对话自己的模型撰写，它会在对话内部撰写摘要，从而复用对话的提示词缓存。参见[模型](/zh/code/configure/models)。
